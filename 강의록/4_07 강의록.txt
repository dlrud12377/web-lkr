 < 리플렉션 >
 - 클래스의 정보(필드, 메서드, 생성자 등)를 프로그램 실행 중에 조회하고 조작하는 기술
 - 로그(log) : 프로그램이 실행되면서 남기는 기록
	- ex. 로그인 시도, 주문내역 저장, 에러 발생 등등

	 < Class 클래스 >
		- 클래스에 대한 정보를 얻고 싶을 때 사용한다.
		- 필드, 메서드, 생성자에 대한 정보도 얻을 수 있다.
		* 사용하는 이유?
			1. 객체를 동적으로 생성할 수 있음
				- 프로그램 실행은 자바코드 작성 -> 컴파일 -> 바이트코드(.class) -> 실행 순으로 진행됨
				- 컴파일 환경 - 컴파일 / 런타임 환경 - 실행 타이밍
				- 일반적인 객체 생성 방식(Car car = new Car();)으로 만들면 컴파일 시점에 클래스가 확정
				- Class clazz = Class.forName("클래스명"); -> **실행 중에 클래스 결정이 가능**
			
			2.  -> 이게 어떤 도움이 되는가?
				- 플러그인 : 기본 프로그램에 외부 기능을 끼워넣는 것(ex. 롤의 op.gg 프로그램, java의 lombok)
				- 보통의 프로그램은 미리 정해진 클래스만 사용하지만, 이런 플러그인의 경우는 실행하기 전까지 어떤 클래스를 쓸지 모르는 경우가 있음
				- 프로그램에 새로운 기능을 나중에 추가하고 싶거나, 설정파일에 따라 다른 객체를 만들고 싶거나, 외부 개발자의 플러그인을 연결하고 싶을때 사용하기 좋음

			3. 프레임워크에서 자동 처리
				- 나중에 우리가 직접 안써도 스프링부트 내부에서 많이 사용중(어노테이션만으로 처리가 가능한 경우가 많음 - 어노테이션 inner process는 메모리 절약을 위해 싱글톤 활용)

 	< 어노테이션@ >
		- 코드에서 @를 붙여 작성되는 요소를 어노테이션이라고 한다.
		- 클래스 또는 인터페이스를 컴파일 또는 런타임 시 어떻게 사용할지 이야기하는 역할을 한다.	
		- 클래스, 필드, 메서드 등에 붙여서 코드에 대한 추가 정보를 전달하는 역할을 한다.
		- ex -> @Override(메서드 재정의 - 오버라이딩 어노테이션)
		- 코드 자체의 실행문은 아니지만, 이 코드가 어떤 의미인지, 컴파일러가 무엇을 확인해야 하는지, 프레임워크가 어떻게 처리해야 하는지와 같은 정보를 알려주는 역할을 한다.
		* 사용하는 이유?
			1. 실수를 줄여줌(자바 프로그램이 실행 의도를 파악하고 미리 워닝사인을 줌)
			2. 코드의 의미 전달이 분명하게 됨(협업자들끼리 공유할때도 한눈에 체크 가능)
	
		- 어노테이션을 직접 만드는 일은 거의 없음
		- 그러나 자바에서 제공하거나(Override, Deprecated, SuppressWarnings) 라이브러리가 제공하는 어노테이션을 사용하는 일이 많음
		- Override, FunctionalInterface, Getter/Setter, ..constr, Controller, Service, Repository, RequestParam, ResponseBody, Entity
		
		< 메타 어노테이션 >
			- @Retention : 언제까지 정보를 유지할것인지
			- @Target : 어디에 정보를 적용할 것인지

		< 커스텀 어노테이션 >
			- public @interface 어노테이션명{}

< 제네릭 >
 - 매개변수 등의 타입을 메서드 내가 아니라 외부에서 지정하는 것(타입을 미리 고정하지 않음)

	< 중첩 타입 파라미터 >
	- 제네릭 안에 제네릭 타입이 들어가는 구조
	- 형식 : Outer < Inner <T> >
	- 복잡한 데이터 구조 표현 가능
	- 타입 안정성 유지
	- 객체 관계를 명확하게 표현

	<제네릭 메서드>
	- 메서드 자체가 타입을 일반화해서 받는 메서드
	- 클래스 전체를 제네릭으로 만드는 게 아니라 특정 메서드 하나만 필요할 때 타입을 유연하게 처리하는 방법
	- 기본 문법 : 접근제한자 < T > 반환타입 메서드명(매개변수) {code}

	< 타입 추론 >
	- 제네릭 메서드를 호출할 때 전달한 값으로 타입을 자동 판단한다.
		- cf) 명시적으로 타입을 부를 때 - p.<String>printValue("안녕"); - 제네릭을 . 뒤에 붙여준다
