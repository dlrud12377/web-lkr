@ - SQL파일을 실행한다.

PL/SQL 테스트를 위한 SQL * PLUS의 활용
 - PL/SQL은 변수, 조건문, 반복문, 예외 처리 등을 사용해서 여러 작업을 절차적으로 처리할 수 있다.
 - 단순히 SQL 실행 결과만 보는 게 아니라, 내부 처리 과정이 맞는지도 확인해야 한다는 것이다.

테스트 항목
실행이 되는가 : 문법 오류 없이 실행이 되는지 확인
출력이 맞는가 : 예상한 값이 출력이 되는지
데이터가 바뀌었는가 : INSERT, UPDATE, DELETE 결과를 해야 한다. -> COMMIT
오류가 없는가 : SHOW ERRORS를 통해 오류를 확인
조건별 결과가 맞는지 : 정상값, 잘못된 값, NULL값 등을 넣어 결과를 확인한다.

 - 프로시저나 함수 사이에 단계별 출력문을 넣어서 테스트를 한다.

SQL  처리 흐름

1. 구문 분석
 - 사용자 요청한 SQL문이 데이터베이스에서 처음 사용된 문장인지, 이미 사용된 문장인지를 공유 풀 영역을 검색하여 확인
 ** 공유 풀 영역 : SQL 실행 계획을 저장하는 메모리 영역(SQL문이 보관되어 있음)

 사용된 적 있는 문장 -> 공유 풀에서 꺼내서 쓰면 됨(구문 분석이 필요없음)
 사용된 적 없는 문장(처음 사용된 문장) -> 구문분석을 실시함

 구문 분석
  - SQL문을 데이터베이스가 이해할 수 있도록 분석하는 작업
  예시
  SELECT NAME
  FROM MEMBER
  WHERE MEMBER_ID = 1;

  ->
  SELECT 문법이 올바른가
  MEMBER 테이블이 존재하는가
  NAME 칼럼이 존재하는가
  MEMBER_ID 칼럼이 존재하는가
  사용자가 MEMBER 테이블을 조회할 권한이 있는가

 - 옵티마이저는 SQL문을 가장 빠르게 데이터를 검색해줄 수 있는 실행 계획을 찾는다.

 ** 옵티마이저
  - SQL을 가장 효율적으로 실행할 방법을 결정하는 데이터베이스 내부 기능

2. 실행
 - 구문분석이 끝난 SQL을 실제로 실행하는 단계
 - 서버 프로세스는 메모리 영역의 데이터베이스 버퍼 캐시 영역을 검색하여 해당 테이블의 데이터가 다른 사용자의 다른 SQL문에 의해 존재하는지 검색

 ** 데이터베이스 버퍼 캐시
 - 실제 테이블 데이터를 저장하는 영역

 버퍼 캐시 영역에 있으면 그대로 사용

 없으면 해당 테이블의 데이터파일에서 데이터를 읽고 버퍼 캐시에 저장함

 INSERT, UPDATE, DELETE와 같은 문장이라면 데이터 버퍼 캐시 영역에서 새로운 데이터로 변경, 삭제 또는 입력을 한다.

3. 추출
 - 실행 결과를 사용자에게 보내주는 단계
 - 서버 프로세스는 데이터베이스 버퍼 캐시 영역에서 관련 테이블 데이터를 읽어서 사용자가 요청한 클라이언트로 보내준다.

 -> SELECT문을 실행하는 경우에만 추출단계가 실행된다.

* SQL 작성 시 고려사항

 - 개발자는 SQL 특성을 충분히 이해하여 SQL문을 적절히 구사할 수 있는 능력을 갖춰야 한다.

 - 사용자가 SQL 작성 시, 옵티마이저가 실행 계획을 수립한 후 실행되는 일련의 과정을 이해하고 작성해야 한다.

 - 구문분석 단계 시 옵티마이저가 수립한 실행 계획에 따라 엄청난 수행 속도 차이가 발생할 수 있다.

 - 특정 SQL이 실행될 때 옵티마이저에 의해 수립된 실행 계획은 제어하기 어렵지만, 옵티마이저가 비상식적으로 동작한다면, 이를 추적하여 개발자가 원하는 실행 계획으로 동작될 수 있도록 조정하는 과정이 필요하다. -> /*+ INDEX(member idx_member_id) */ 이런식으로 디렉션 주기

 - 개발자는 옵티마이저가 정상적인 실행 계획을 수립할 수 있도록 종합적이고 전략적인 포인트를 SQL에 부여하여 작성하여야 한다.

 - 좋은 SQL은, 추출되는 결과를 추론하여 SQL을 집합적으로 접근하여 작성하여야 한다.

테스트 조작 프로시저 성능 개선하기

1. 분석가에 의해 정의된 유가사항(유의사항?)을 기준으로, 성능 측정 도구를 활용하여 데이터 조작 프로시저의 성능을 측정한다.
 - 응답 시간, 처리 건수, 리소스 사용량 등을 목표로 분석하고 테스트 대상 성능 기준을 정의한다.
 - 성능 도구 설정, Trace 로그 수집을 준비
 - 테스트용 데이터를 사용하여 프로시저를 실행하고, 실행 결과 및 Trace 로그 수집을 진행
 - 결과를 분석하여 지표를 검토

2. 실데이터를 기반으로 텍스트를 수행하여 데이터 조작 프로시저의 성능에 영향을 주는 병목구간을 파악한다.
 - 운영 데이터의 복사본 또는 유사 데이터를 준비하여 성능 테스트 환경 구성
 - 대량 처리, 복합 조건, 동시성 등 다양한 상황을 반영하여 테스트 시나리오 작성
 - PL/SQL 블록 실행 또는 SQL script 반복실행을 통해 성능 데이터 수집
 - 병목 지점 식별
 - 성능 저하 원인 보고서 작성

3. 테스트 결과와 정의된 요구사항을 기준으로 데이터 조작 프로시저의 성능에 따른 이슈를 해결한다.
 - 속도를 저하시키는 SQL 구문을 재작성하여 성능을 개선한다.
 - 실행 계획을 개선한다.
 - 인덱스를 재구성한다.
 - 시스템 리소스 병목 구간을 조정한다.
 - 개선 후 동일한 테스트로 효과를 검증한다.
 - 성능 개선 결과를 문서화 하고 공유한다.
