[문제]

1. 
최근 연계 데이터 생성 및 추출 기술로 자주 활용되는 CDC(Change Data Capture)의 개념과 작동 원리를 서술하시오.

운영 DB의 트랜잭션 로그를 실시간으로 감지하여, 전체 데이터를 조회하지 않고 데이터의 추가, 변경, 삭제 등의 데이터 변화가 일어났을 때 변경된 부분만을 실시간으로 감지하여 추출하는 기술 또는 프로그램을 의미한다.

2.
송수신 시스템 사이에서 어댑터(Adapter) 및 중계 서버 역할을 수행하는 API Gateway의 개념과 주요 기능 2가지를 서술하시오.
 - 송/수신 시스템(서로 다른 서비스 및 시스템) 사이에서, API 호출을 단일 엔드포인트로 통합하여 데이터 포맷, 통신 프로토콜, 보안 정책의 차이를 완화해주는 중계형 미들웨어/플랫폼이다.
 - 주요 기능 : 		
		 - 데이터/프로토콜 변환 : [JSON -> XML], [REST -> FTP(gRPC)] 변환
		 - 메시지 라우팅 : 목적지 시스템 지정 전송
		 - 보안 제어 : OAuth2, JWT 등을 통한 데이터 암/복호화, 인증/인가, 접근 제어
		 - 오류 관리 & 재처리 : 전송 실패 시 실패 데이터만 재전송

연계 메커니즘에서 **인터페이스 테이블(I/F Table)**의 개념과 이를 두는 주요 목적 2가지를 서술하시오.

3. 
인터페이스 테이블(I/F Table) 또는 인터페이스 파일이란 송신 시스템과 수신 시스템 간의 데이터 연계를 위해 데이터를 바로 반영하지 않고 임시로 저장하는 중간 저장 DB 영역을 의미한다.

인터페이스 테이블의 목적
- 시스템 간 차이 완화 : 송수신 시스템의 스키마, 데이터 포맷, 전송 주기의 차이를 해소한다.
- 

4. 
연계 메커니즘에서 **로그(Log)**의 개념을 정의하고, 로그 테이블에 필수적으로 기록되어야 하는 주요 항목 3가지를 쓰시오.

 - 송신 시스템과 수신 시스템 간 데이터 연계 과정에서 발생하는 모든 처리 이력과 결과를 시간순으로 기록하고 저장한 데이터이다.

 필수 기록 항목 3가지
1. 송수신 일시
2. 인터페이스 ID 또는 테이블/파일명
3. 처리 단계 및 결과 상태
4. 처리 건수
5. 오류 코드 및 에러 메시지

------------------------------------------

5. 
시스템 간 데이터 연계 과정에서 발생하는 연계 오류의 정의를 쓰고, 발생 원인에 따른 연계 오류의 3가지 유형을 각각 서술하시오.

정의
 - 연계 과정에서 데이터가 정상적으로 전송, 수신, 저장, 처리되지 못해 발생하는 문제를 말한다.

연계 오류의 유형
 1. 연계 시스템 오류(인터넷 선이 끊기거나 서버 컴퓨터가 꺼진 경우)
 2. 연계 프로그램 오류(데이터 변환 프로그램에 버그가 있는 경우)
 3. 연계 데이터 오류(필수 정보인 '이름'이나 '전화번호'가 빈칸으로 온 경우)


6. 
장애 및 오류 로그(Log)의 개념을 서술하고, 시스템 운영 환경에서 오류 로그를 활용할 수 있는 방안 2가지를 쓰시오.

정의
 - 시스템이나 프로그램에서 처리 중 발생한 장애나 오류 상황을 기록한 데이터이다.

활용 방안
 - 오류 식별 : 근본 원인을 규명
 - 해결 시간 단축 : 신속한 장애 조치 가능
 - 데이터 신뢰성 확보 : 영향 범위를 명확히 파악하여 데이터 정합성 유지
 - 시스템 안정성 확보 : 장애 패턴 추적을 통한 사전 예방
 - 감사 및 규제 대응 : 법적 증거 자료로 활용


7. 
연계 장애 발생 시 신속한 원인 파악을 위해 수행하는 **'1차 확인(대시보드)'**과 **'2차 확인(로그 심층 분석)'**의 구체적인 수행 내용을 서술하시오.

1차 확인(대시보드) : 장애 탐지 대시보드에서 장애 여부, 알람 발생 여부, 트렌드를 파악한다.
(Prometheus, Grafana, ELK, Datadog의 프로그램으로 확인)

2차 로그 심층 분석 : 로그와 메타데이터를 분석한다.

분석 시 사용 프로그램
	- 로그 심층 조회 : Log Explorer
	- Kibana
	- CloudWatch Logs

 장애 시각 및 컨텍스트 분석
	- TraceID 활용
	- CorrelationID 활용


8. 
장애 로그를 '기록 단위' 기준으로 분류할 때, 시스템 로그, 연계(인터페이스) 로그, 데이터 로그의 개념적 차이를 각각 설명하시오.

 - 시스템 로그 : 연계 서버 자체의 실행/접속/전송에 대한 상태 등 시스템 기능을 전반적으로 기록
 - 연계 로그 : 송수신 데이터 단위의 전송/변환/처리 등 오류 기록
 - 데이터 로그 : 개별 Row, 데이터 필드 단위로 상세 오류 기록

9. 
최신 기술 환경인 MSA(마이크로서비스 아키텍처), AIOps, DevOps 중 하나를 선택하고, 해당 환경에서 요구되는 장애 처리 및 모니터링의 핵심 특징을 서술하시오.

MSA : 큰 시스템 하나를 독립적으로 배포 가능한 여러 개의 작은 서비스(모듈)로 쪼개어 개발하는 아키텍쳐이다 보니, 서비스 단위별 장애 추적이 필요하다.
AIOps : 인공지능과 머신러닝 기술을 운영 및 모니터링/대응 프로세스에 결합한 기술이며, 머신러닝 모델이 평소 정상 로그 패턴 학습 후  대량의 로그를 확인하고 이상 징후를 실시간 탐지 및 원인 제시를 해준다.
DevOps : 개발과 운영을 하나로 융합하여 진행하는 조직 문화 및 방법론이며, 장애를 완벽하게 막는 것보다 얼마나 빠르게 탐지하고 복구하는가를 핵심지표로 삼는다.
