< OOP 4대 개념 >

 - 캡슐화
	 - 데이터를 보호하는 개념
	 - 필드에 직접 접근하지 못하게 함(보안)
	 - 제공된 메서드인  getter, setter라는 public 메서드를 사용하여 pritvate field를 간접적으로 접근할 수 있게 한다.

 - 상속
	 - 기존 클래스의 내용을 물려받는 기능(필드, 메서드)
	 - 코드를 재사용할 때 좋음
	 - 프로그램을 구조화할 때 상하개념을 명확하게 만들어줌

 - 다형성
	 - 하나의 타입으로 여러 객체를 다룰 수 있는 성질
	 - 오버라이딩 : 상속 관계에 있는 부모 클래스의 메서드를 재정의하여 자식 클래스에서는 다른 결과가 출력되게 하는 방식 
	 - 오버로딩 : 하나의 클래스에 있는 같은 이름의 메서드를 매개변수의 개수, 반환 타입 등을 이용해 여러번 재정의하여 다양한 결과가 나오도록 하는 방식
	 - 캐스팅 : 하나의 변수를 다양한 타입의 변수로 바꾸어 쓸 수 있어 다형성에 해당
	 - 상속 관계의 클래스는 오버라이딩과 타입캐스팅을 통해 다양한 결과를 창출할 수 있음 

 - 추상화
	 - 클래스를 핵심만 추출하여 단순화 시키는 것
	 - abstract를 이용하여 구현하는 추상클래스가 대표적인 예시
	 - abstract가 붙은 추상클래스는 최소 한 개의 추상메서드를 가져야 한다.
	 - 추상메서드는 자식 관계의 클래스들마다 공통적인 속성 또는 메서드가 있지만 기능이 달라 메서드 오버라이딩이 필요한 경우에 사용이 된다. 다만 부모 클래스에서 구현 가능한 공통적인 사항은 구체적으로 작성하여 완성시켜도 문제없다.
	 - 추상 메서드는 스스로 객체 생성이 불가능하고, 클래스를 상속하여 구체화하는 자식 클래스가 필요하다.
	 - 인터페이스는 추상 클래스와 유사하나, 화면에 사용할 수 있는 기능만을 열거하듯이 전부 구현되지 않은 상태인 메서드와 public static final이 붙은 상수로만 구성이 된다.


 < 자바 변수 명명 규칙 >

 - 카멜 표기법을 사용하여 시작은 소문자로, 이어지는 단어의 시작은 대문자로 진행한다.
 - 첫 문자는 숫자로 시작할 수 없다,
 - 특수 문자는 _ 와 $만 허용
 - 대소문자가 구분되어 다른 변수로 작용한다.
 - 자바에서 사용하는 예약어는 이름으로 사용할 수 없다.

< 오버라이딩 vs 오버로딩 자세히 비교 >
 - 오버라이딩 : 상속 관계의 두 클래스에서 부모 클래스에 정의된 메서드를 자식 클래스에서 재정의하기 위해 **메서드명, 반환타입, 매개변수** 를 동일하게 구성한 같은 클래스의 내부 코드를 바꾸어 실행하는 것. 이를 통해 부모 클래스와 자식 클래스에서 같은 메서드를 호출하더라도 다른 결과가 나오게 함

 - 오버로딩 : 하나의 클래스 내에서 같은 이름의 메서드를 **반환 타입, 매개변수 개수 및 매개변수의 타입를 다르게** 하여 여러 번 정의하는 것. 이를 통해 동일한 메서드를 사용하였을 때, 넣은 매개변수의 타입 및 개수에 따라 결과값이 다르게 나오게 됨.


 < 제네릭 타입 >
 1. 타입을 미리 결정하지 않고 실행시 결정하는 문법. 주로 <T>를 사용하여 표시하며, T 자리에는 영어 대문자기호 아무거나 들어가도 되지만, 내부에 들어갈 값의 방향성에 따라 암묵적으로 정해둔 기호들이 있다.(ex. K , V -> key and value)

 2. 제네릭을 사용하면 타입이 미리 결정된 이전 문법의 경우 타입이 결정되어 안정성이 없지만, 제네릭은 타입 미결정임에도 상하한제한(extends super)이 있어서 캐스팅 및 프로그램상 사용하도록 의도된 여러 타입을 다루기에 적합하다.

 3. 제네릭 클래스는 클래스가 필드 또는 메소드의 매개변수 등을 제네릭 타입으로 가지며, 클래스명 옆에 <>를 붙여 선언한다.
제네릭 메서드는 클래스 자체는 제네릭 타입 표시가 없으나, 특정 메서드만 제네릭 타입을 사용하고 싶을때 메서드명 옆에 <>를 붙여 사용한다.

 4. 제네릭 타입을 사용하지 않으면 보통 object 타입을 활용하게 된다.
- 오브젝트 타입은 사용시 명시적 형변환을 계속 해주어야 하여 데이터 활용 시 불편함을 초래한다.
- 또한 명시적 형변환 이후에도 데이터 타입이 혼용되어 코드의 재사용성과 가독성이 저하한다.

 < 컬렉션 프레임워크 >
1~2.
 (1). List
	- 기존 배열과 가장 유사한 인터페이스이다.
	- 기존 배열과 마찬가지로 인덱스값을 이용해 순서를 보장하며, 순서 개념이 있으므로 중복되는 값도 허용된다.
	- 다만 배열은 길이가 결정되면 더 큰 배열로 복사를 해서 길이 조정을 해야하지만, 리스트는 자유롭게 길이 조절이 가능하다.
	- ArrayList, LinkedList 등을 구현 클래스로 가진다.

 (2). Set
	- 수학의 집합 개념과 거의 같은 인터페이스이다.
	- 인덱스값이 존재하지 않으며, 이는 순서를 보장하지 않는다는 뜻이므로 중복되는 값은 허용되지 않는다.
	- 길이는 리스트와 동일하게 변경이 자유롭다.
	- Set, HashSet 등을 구현 클래스로 가진다.

 (3). Map
	- 두 개의 값을 묶어서 가지는 형태의 자료구조를 관리하는 인터페이스이다.
	- 두 값 중 앞의 값은 Key, 뒤의 값은 Value라고 하며, Key는 인덱스의 역할, Value는 인덱스에 해당하는 값 역할을 한다.
	- 따라서 순서는 따로 없다. 다만 Key값이 구분을 하는 역할을 하기 때문에 Value의 값은 중복이 되며, Key값은 중복되지 않는다.
	- Map, HashMap 등을 구현 클래스로 가진다.

 3. List의 경우 위에서 기술한 대로 순서가 보장되며, 길이 변형이 자유로워 중복 가능성이 있는 단일값을 관리할 때 유용하다.
 Set의 경우 순서가 보장되지 않고 중복이 보장되지 않으므로, 중복 데이터를 제거해야 하거나 원하는 값을 조회할 때 값이 하나이므로 뛰어난 성능을 보여준다.
Map의 경우 두 개의 정보를 연관지어 저장할 수 있으므로, 주로 이름 - 개인정보 형태로 저장해야 하는 각종 정보 관리 시스템에서 큰 강점을 보인다.

 < 람다식 >

 1. 람다식은 익명 함수를 사용하여 메서드를 하나의 식으로 간결하게 표현한 것이다.
- 객체 지향형 언어인 자바에 부족한 코드의 간결성과 가독성이 향상되는 효과를 얻고, 함수형 프로그래밍을 도입해 무슨 데이터를 처리할지에 집중하기 위해 등장했다.

 2. 
익명 클래스
- 클래스 내부에 메서드가 몇 개가 있어도 상관없다.
- 인터페이스에서 주어진 모든 메서드를 오버라이딩 해야한다.
- 코드가 람다식에 비해 간결하지는 않으나, 많은 메서드를 한번에 다룰때는 람다식에 비해 이점을 갖는다.

람다식
- 함수형 인터페이스 전용으로, 인터페이스당 단 하나의 추상메서드만을 갖는다.
- 메서드를 하나만 사용하기 때문에 메서드명부터 변수 등 많은 것을 생략 가능해 코드가 매우 간결해진다.
- 코드가 간결해지므로 가독성도 익명 클래스에 비해 우수하다.
- 컬렉션 프레임워크를 다룰 때 편하다.(향상된 for문, 자바 함수형 인터페이스 등..)

3. 함수형 인터페이스는 위에서 람다식을 설명할 때 기술했던대로, 1개의 추상메서드만 갖는 인터페이스를 의미한다.

4. 
	1. 코드의 간결성과 가독성이 증가한다.
	2. 코드의 재사용성이 증가하며, 익명클래스를 선언하지 않아 불필요한 과정이 감소하여 생산성이 증가한다.
