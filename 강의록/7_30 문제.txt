문제 1

A회사는 ERP와 CRM을 연계하여 회원 정보를 전송하고 있다.

다음과 같은 상황이 발생하였다.

ERP 서버 : 정상
네트워크 : 정상
CRM 서버 : 정상
회원 등록 중 다음 오류가 발생하였다.
오류코드 : EAD001

등록된 회원이 이미 존재합니다.
조건

다음 내용을 작성하시오.

연계 오류의 유형 : 연계 데이터 오류
오류의 원인 : 수신 시스템의 운영 DB에 이미 존재하는 회원의 식별키를 송신 시스템에서 신규 등록하려고 시도하여 발생(PK 중복)
해결 방안 : 
 - 수신 시스템 반영 로직을 기존 회원 존재 여부에 따라 수정/신규로 분기 처리
 - 송신 전 데이터 중복 검증 로직 추가하기(원본 데이터 보정 및 재처리)

해결 후 확인해야 하는 사항 2가지
 - 로그가 success로 변경되었는가?
 - 수신 I/F 테이블에 저장되었는가?
 - 운영 DB에 정상 반영되었는가?
 - 중복 데이터가 없는가?
 - 사용자 화면에서도 정상적으로 보이는가?

 - 로그 확인 : 수신 시스템의 처리 로그에서 정상 처리 메시지및 에러 재발 여부 확인
 - 운영 DB 정합성 확인 : CRM DB 내 해당 회원 정보가 누락이나 중복 없이 정확하게 반영되었는지 조회하여 데이터 검증

문제 2

쇼핑몰 주문 시스템에서 주문 데이터를 물류 시스템으로 전송하고 있다.

현재 송신 시스템은 JSON 형식으로 데이터를 전송하고 있으며, 물류 시스템은 XML 형식만 처리할 수 있다.

로그에는 다음과 같은 메시지가 출력되었다.

JSON → XML 변환 실패
조건

다음 내용을 작성하시오.

오류 유형 : 연계 프로그램 오류( 데이터 변환 / 코드 매핑 로직 오류 )
오류 원인 : 연계 서버의 데이터 변환 프로그램 파서가 JSON	 데이터를 XML 규격으로 정상 변환하지 못하거나, JSON 구문 오류로 인해 변환을 실패함
해결 방안 : 프로그램 로직 수정
	- 연계 서버 / 어댑터의 데이터 변환 모듈을 점검하여, JSON-to-XML 매핑 규칙 및 파서 구성을 수정
	 적용해야 하는 작업 : JSON → XML 데이터 포맷 매핑 규칙 적용 및 데이터 변환 프로그램 수정

적용해야 하는 작업 : 
	JSON → XML 변환 로직을 수정한다.
	코드 매핑 규칙을 올바르게 수정한다.
	수정된 프로그램을 배포한다.
	실패한 데이터를 재처리(재전송)한다.

해결 여부 확인 방법 : 
	변환 오류 로그가 더 이상 발생하지 않는지 확인한다.
	로그 상태가 SUCCESS로 변경되었는지 확인한다.
	수신 I/F 테이블에 데이터가 정상 저장되었는지 확인한다.
	물류 시스템 운영 DB에 데이터가 정상 반영되었는지 확인한다.
	중복 저장이 발생하지 않았는지 확인한다.

	- 변환 로그를 통해 JSON -> XML 변환 성공 처리 이력을 확인하고, 물류 시스템 DB/인터페이스 테이블에 데이터가 정상 적재되었는지 확인

문제 3

ERP에서는 사용자 권한을 다음과 같이 관리한다.

SUPER

CRM에서는 다음 코드만 등록되어 있다.

ADMIN

연계 프로그램을 실행한 결과 다음 오류가 발생하였다.

오류코드 : EAC001

등록된 코드가 없습니다.
조건

다음 내용을 작성하시오.

오류가 발생한 이유 : 연계 데이터 오류(코드 매핑 오류), ERP의 사용자 권한 코드(SUPER)와 CRM의 권한 코드(ADMIN)가 서로 다르며, 코드 매핑 규칙이 정의되어 있지 않아 CRM에서 해당 코드를 찾지 못했기 때문(매핑이 실패했기 때문)이다.
해결 방법 : 코드 매핑을 하거나, 두 곳에서 권한의 이름을 일치시키거나, 중간에 연계 시 자동 변환을 해주는 인터페이스 테이블을 둔다.
 - 연계 서버 또는 수신 어댑터의 코드 매핑 테이블에 ERP의 SUPER 코드를 CRM의 ADMIN 코드로 1:1 변환되도록 등록/수정

동일한 문제가 다시 발생하지 않도록 예방 관리 방법 2가지를 작성하시오.

① 코드 매핑 테이블을 지속적으로 관리한다.

새로운 코드가 추가되면 함께 등록하여 미등록 코드가 발생하지 않도록 한다.

 - 표준 코드 통합 관리 체계 구축 : 시스템간 표준 코드를 정의하고 중앙 집중식 매핑 테이블 운영

② 데이터 검증 규칙을 추가한다.

전송 전에 코드가 존재하는지 검사하고,
등록되지 않은 코드는 오류 로그를 남기거나 전송하지 않는다.

  - 코드 변경 시 사전 검증 프로세스 수립 : 코드 신규 등록 / 변경 시 연계 프로그램과 매핑 여부를 사전에 검증

예약 데이터는 정상적으로 전송되었다.
진료 시스템 DB에는 데이터가 저장되지 않았다.
로그에는 다음 내용이 기록되었다.
오류코드 : EAD001

PK 중복
조건

다음 내용을 순서대로 작성하시오.

오류 식별 방법 : 연계 서버 및 수신 시스템 로그에서 오류코드와 메시지를 확인

오류 원인 분석 방법 : 송신 시스템의 PK 생성 규칙과 수신 시스템 DB의 기존 PK값을 비교 분석하여 데이터 중복 로직의 결함 여부 확인

 - PK 자동생성 로직을 수정하여 중복 방지

 - 연계 재시도 후 로그에서 pk 중복 에러가 사라졌는지 확인하고, 진료 시스템 운영 db에 예약 데이터가 정상 적재되었는지 확인

 - 오류 발생 일시 및 코드
 - 오류 발생 원인 및 대상 데이터
 - 조치 내용 및 해결 방안
 - 조치자 및 조치 완료 일시

문제 5

ERP와 CRM을 연계하여 고객 정보를 전송하고 있다.

다음과 같은 상황이 발생하였다.

송신 프로그램 : 정상
데이터 : 정상
연계 서버 : 정상
방화벽 정책 변경으로 Port가 차단되었다.
고객 정보가 CRM으로 전달되지 않았다.
조건

다음 내용을 작성하시오.

오류 유형 : 연계 시스템 오류(네트워크/보안 환경 오류)
오류 원인 : 방화벽 정책 변경으로 인해 연계 통신용 포트가 차단되어 CRM 시스템으로의 데이터 전송 트래픽이 거부됨
해결 방안 : 네트워크/보안 관리자에게 연계 서버 및 수신 시스템간 IP/PORT 방화벽 정책 예외 등록 요청

해결 후 확인해야 하는 사항 3가지
 - 네트워크 포트 연결성 확인 : Telnet 또는 Ping을 통한 IP/PORT 통신 정상 여부 점검
 - 로그 확인 : 연계 서버 및 송신 어댑터의 전송 성공 로그 확인
 - 미전송 데이터 재처리 : 차단 기간 동안 누락된 대기 데이터를 재전송하여 CRM 반영 완료 여부 확인

동일한 문제가 다시 발생하지 않도록 예방 관리 방법 2가지를 작성하시오.
 - 네트워크/보안 정책 변경 전 연계 영향도 사전 검토 : 방화벽 정책 변경 시 연계 포트 포함 여부를 사전 검증하는 절차 마련
 - 실시간 모니터링 및 알람 체계 구축 : 포트 차단이나 네트워크 장애 발생 시 즉시 담당자에게 알림이 가도록 관제 설정
