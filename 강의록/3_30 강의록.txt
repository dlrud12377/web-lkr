 < 3/30 강의록 >

	1. 참조용 클래스(객체를 만들기 위한 클래스)
		- 메인 메서드가 없음

		- 필드와 메서드로 구성

		- 생성자(호출 시 객체를 메모리에 올려주는 기능)
			- 객체 생성 시 필드 초기화하는 역할
			- 사용자가 정의하지 않으면 컴파일러가 기본생성자를 만들어서 사용한다.
				->정의를 하면 컴파일러의 기본생성자는 사용되지 않는다.
				+ 메서드처럼 매개변수를 가질 수 있다.

	2. 메서드
		- 정의(기능을 만드는 것)
			- 숫자 두개와 연산자를 받을 준비

		- 호출
			- 숫자와 연산자를 전달하여 연산결과를 돌려받는다.

		- 사용 : 접근제한자 (정/동적) 변수타입 {실행할 코드}

		- return : 매개변수, 메서드 내부에서 정의된 변수는 지역변수이고, 메서드가 호출되서 실행 후 종료되면 삭제됨
			-> 만약 메서드 밖에서 연산결과를 사용하고 싶다면, return을 통해 값을 밖으로 꺼내야 함

		- 메서드명 : 메서드를 호출할 때 사용하는 이름. 첫 글자는 소문자로 작성

	3. 오버로딩(overloading) : 같은 이름으로 서로 다른 개수, 타입의 매개변수를 각각 처리하는 방법
		- 반환형은 달라도 상관 없음
		- 메서드(또는 생성자)명은 같아야 한다.
		- 매개변수의 개수가 다르거나, 타입이 다르거나, 순서가 달라야 한다.


	4. 접근 제한자(Access Modifier)
		- public : 프로젝트 내에서 어디서든 사용 가능
		- default : 같은 패키지 내의 다른 클래스 어디든지 사용 가능
		- private : 현재 클래스에서만 사용 가능
		- protected : 상속관계에서만 사용 가능

	- 필드/생성자/메서드/클래스에 붙일 수 있음,

	
	** 디자인 패턴
		- 프로그래밍을 하다 보면 비슷한 문제가 반복적으로 나타나는 경우가 있음
			- 객체를 하나만 만들어야 하는 경우
			- 객체 생성이 너무 복잡한 경우
			- 기능은 비슷한데 구현 방법이 여러개인 경우
			- 객체들끼리 너무 강하게 연결되어 있어 수정이 어려운 경우


	5. 상속
		- 특징
			- 하나의 부는 여러 클래스에게 상속이 가능하나, 하나의 자식이 여러 클래스를 상속받는 것은 불가능
