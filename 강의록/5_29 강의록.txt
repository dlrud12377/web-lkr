 PK - FK 연결되어 있는 두 개 테이블의 데이터에 대한 제약조건

 삭제했을 때
 - CASCADE : PK 값이 삭제되면 FK 쪽에서도 같이 삭제된다.
 - RESTRICT : PK값이 삭제되려 할 때 FK쪽에서 사용(참조)중이면 삭제가 불가능하게 막는다.
 - NULLIFY : PK쪽 값이 삭제되면 FK쪽에서는 NULL로 바꾼다.

 수정했을 때
 - CASCADE : PK 값이 수정되면 FK 쪽에서도 같이 수정된다.
 - RESTRICT : PK값이 수정되려 할 때 FK쪽에서 사용(참조)중이면 수정할 수 없게 한다.
 - NULLIFY : PK쪽 값이 수정되면 FK쪽에서는 NULL로 바꾼다.

 사용위치 : 테이블 만들 때 외래키 제약조건 밑에 같이 속성을 작성

 < 인덱스 >

??

 - 조회 성능을 높이기 위해 어떤 컬럼에 인덱스를 적용시켜줘야 할까?

 인덱스 컬럼의 분포도가 10 ~ 15% 이내가 일반적이다.
 분포도의 값이 적을수록 인덱스 효율이 높다 -> 분포도가 넓다

 분포도 = (1 / 도메인의 수) * 100

 조회 및 출력 조건으로 사용되는 컬럼인 경우
 - WHERE에서 많이 사용되는 컬럼인가

 PK와 UNIQUE를 지정한 컬럼은 인덱스가 자동으로 만들어진다.

 수정이 빈번하지 않은 컬럼을 선정한다.

 자주 조합되서 사용되는 컬럼은 결합 인덱스로 생성

 뷰(VIEW)
 - SELECT를 한 결과를 저장하는 가상의 테이블

 뷰의 속성
 REPLACE
 - 뷰가 이미 존재하는 경우 기존 뷰를 새 내용으로 다시 생성하는 속성
 형식 : CREATE OR REPLACE VIEW_NAME AS..


 FORCE
 - 기존 테이블이 존재하지 않아도 뷰를 생성하는 속성
 - ORACLE에서 사용됨
 - 단, 뷰를 사용하려고 하면 에러가 발생

 NOFORCE
 - 기본테이블이 존재할 때만 뷰를 생성할 수 있게 함

 WITH CHECK OPTION
 - 뷰의 조건을 만족하는 행만 INSERT 또는 UPDATE 할 수 있도록 제한하는 속성

 WITH READ ONLY
 - 뷰를 읽기 전용으로 만드는 속성

 뷰 설계 시 고려사항
 - 결국 VIEW 안에 SELECT문을 실행하는 프로세스이기 때문에 데이터가 많으면 조회가 느릴 수 있다.
 - 뷰 안에 조건이 있다면, 해당 조건 컬럼에 인덱스가 걸려있는지 확인

 클러스터
 - 자주 같이 조회되는 데이터를 디스크의 가까운 위치에 저장해서 조회 속도를 높이는 물리적 저장 방법

 - 데이터가 많은 경우
