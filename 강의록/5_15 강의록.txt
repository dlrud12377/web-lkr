 < 요구사항 확인 >
	1. 현행 시스템의 분석
		-  새 시스템을 만들거나, 기존 시스템을 개선하기 위해 현재 사용중인 업무 방식, 프로그램, 데이터, 서버, 네트워크, 문제점을 조사하고 정리하는 활동

	2. 목적
		- 새로운 시스템을 정확하게 만들기 위해 현재 상황을 이해한다.

	3. 요구사항을 확인하지 않았을 때의 문제점
		(1). 기존 업무의 흐름을 모른다면 필요한 기능을 빠트릴 수 있다.
		(2). 기존 데이터 구조를 모른다면 데이터 이전 시 오류 발생
		(3). 기존 시스템 연동을 모른다면 외부 시스템과 연결이 실패할 수도 있다.
		(4). 사용자 불편 사항을 모른다면 새 시스템을 만들어도 만족도가 낮다.
		(5). 현재 원인을 모른다면 문제 해결이 아닌 단순 재개발이 된다.

	4. 현행 시스템 파악 절차
		- 1단계 : 현행 시스템의 구성, 기능, 인터페이스 현황 파악
			- 현재 시스템이 무엇으로 구성되어 있고, 어떤 기능을 제공하고, 어떤 프로그램과 연결되어 있는지 파악

		- 2단계 : 시스템 구성현황 파악
			- 현재 운영중인 시스템의 종류와 역할을 정리하는 것
			ex. 	수강생 관리 시스템 - 관리자 - 수강생 등록, 수정, 조회
			    	출결 관리 시스템 - 강사, 관리자 - 출결 관리
				상담관리 시스템 - 상담 직원(관리자) - 상담 이력 관리
				결제 관리 시스템 - 관리자 - 수강료 결제 내역 관리
				문자 발송 시스템 - 관리자 - 공지 문자 발송

	5. 기능 현황 파악
		- 각 시스템이 제공하는 기능을 정리하는 것

	수강생 등록 시스템
	수강생 등록 : 신규 수강생을 등록
	수강생 조회 : 학원에 다니는 수강생을 조회
	수강생 수정 : 수강생의 정보를 수정
	수강생 삭제 : 잘못 등록된 수강생 정보를 삭제

	1단계 : 인터페이스 현황 파악
	- 시스템과 시스템이 데이터를 주고받는 연결 지점을 의미
	- ex. 쇼핑몰 프로그램
		결제 api -> 주문번호, 결제금액, 결제상태
		택배사 api -> 주문번호, 주소, 송장번호
		문자발송 api -> 전화번호, 메시지 내용
		이메일 api -> 이메일 주소, 인증 코드
		
		cupang.com/search?q=데이터  // q : query

	2단계 : 현행 시스템의 아키텍처 및 소프트웨어 구성 현황 파악
		- 현재 시스템이 어떤 구조로 만들어져 있고, 어떤 소프트웨어를 사용하고 있는지 파악

		- 아키텍쳐 현황 파악
			- 현재 시스템이 어떤 구조로 만들어져 있는지 조사하는 일
			**아키텍처 : 시스템의 구성

		- 소프트웨어 구성 현황 파악
			- 현재 시스템이 어떤 소프트웨어를 사용하고 있는지 조사

		- 2단계 산출물
			- 시스템 아키텍쳐 구성도
			- 클라이언트부터 인프라까지 전체 구성을 한 눈에 파악할 수 있음
			- 소프트웨어 구성 목록
				- 시스템을 구성하는 소프트웨어를 영역별로 정리한 목록
			- 소프트웨어 버전 현황표
				- 현재 사용 버전, 최신 버전, 업데이트 상태를 한 눈에 파악할 수 있는 표
			- 기술 스택 정리표
				- 역할별 기술 스택을 목적, 선택 이유, 대안까지 함께 정리한 표

	3단계 : 하드웨어 및 네트워크 분석
		- 현재 시스템이 운영되는 물리적 또는 클라우드 인프라 환경을 파악한다.

	서버는 어디에서 운영되는지?
	서버 사양은 어떻게 되는지
	네트워크는 어떻게 연결되어 있는지
	방화벽이나 보안 설정은 어떻게 되어있는지

	하드웨어 구성 현황 파악
	- 서버, 저장장치, 백업 장비, 보안 장비 등의 정보를 정리하는 것
	- 클라우드 환경이라면 EC2, RDS, S3같은 자원을 확인한다.

	** 포트(port)
	- 외부와 데이터를 주고받는 통로이자 접속 지점

	SSL(Secure Sockets Layer) 인증서
	- 웹사이트와 사용자 브라우저 간 데이터를 암호화하여 개인정보 노출을 막는 디지털 보안 솔루션
	- 데이터 암호화 : 제 3자가 내용을 볼 수 없도록 보호
	- 데이터 무결성 : 데이터가 인증 중 변조되지 않도록 보호
	- 신원 인증 : 클라이언트가 접속하는 서버가 신뢰할 수 있는 서버인지 확인
	

	캐시(Cache)
	- 자주 사용하는 데이터나 값을 미리 복사해 놓는 임시 장소를 가리킨다.
	- 저장공간이 작고 비용이 비싼 대신 빠른 성능을 제공한다.

	- 발열이 심하고 너무 비싸져서 현실성이 없음

문제 1. 운영체제의 역할 설명하기

운영체제(OS)의 역할을 설명하고, 운영체제가 없는 경우 어떤 문제가 발생하는지 작성하시오.

 - 컴퓨터의 하드웨어와 소프트웨어 자원을 관리하며, 프로그램이 실행될 수 있도록 공통 서비스를 제공함
 - CPU, 메모리, 디스크 등을 프로그램에 할당한다.
 - 사용자와 컴퓨터 사이의 중간관리자 역할을 한다.

문제점
 - 운영체제가 없으면 하드웨어 자원을 관리할 주체가 없어 사용자와 기계 간의 인터페이스가 성립되지 않는다.
	 - 소통할 수 있는 화면이 없어서 애초에 장치를 사용할 수가 없다
 - cpu와 메모리를 직접 제어해야 한다.
 - 여러 프로그램을 동시에 실행할 수 없다.

문제 2. 운영체제 종류 구분하기

다음 운영체제의 특징을 작성하시오.

Windows : GUI / CLI 모두 지원하며, 일반적인 개인용 PC나 프로그램(+ 중소규모용 서버)에 사용된다. LINUX에 비해 GUI 사용으로 인해 메모리 사용량이 높아 더 높은 서버 사양이 필요하다.
Linux : CLI만을 지원하지만 메모리 사용이 가볍다는 장점 + 무료 때문에 서버관리용으로 많이 사용된다.
UNIX : 다중 사용자(Multi-user) 및 다중 작업(Multi-tasking)을 지원하여 대규모 서버 환경에서 안정적이고 이식성이 높다.


문제 3. 신뢰도 요구사항 분석하기

온라인 쇼핑몰 서버는 24시간 운영되어야 한다.
운영체제 선정 시 신뢰도가 중요한 이유를 작성하시오.

 - 신뢰도는 장기간 시스템을 운영할 때 운영체제 고유의 장애가 발생할 가능성을 의미함
 - 운영체제 자체의 문제로 인해 시스템이 멈추거나 느려지거나 재부팅이 필요하게 되면, 사용자가 시스템 관련한 어떠한 프로세스도
진행이 어려워질 수 있다.
 따라서 신뢰도가 중요한 이유는
 - 서버가 장기간 안정적으로 동작해야 하기 때문이다.
 - 메모리 누수 발생 시 성능 저하가 발생할 수 있다.
 - 보안 패치 및 버그 수정 시 안정적인 운영이 필요하다.
 - 서버 중단 시 결제 오류와 서비스 장애가 발생할 수 있다.

문제 4. 메모리 누수 설명하기

메모리 누수(Memory Leak)의 개념과 문제점을 작성하시오.

 - 메모리 누수란 프로그램이 사용한 메모리를 다시 반납하지 않는 문제이다.

 - 프로그램은 실행 중에 메모리를 사용하는데, 문제 프로그램은 사용 후 이 메모리를 반납하지 않아 누수가 발생하며,
 - 이 경우
	- 메모리 사용량이 계속 증가한다.
	- 서버 속도가 느려진다.
	- 프로그램 오류가 발생할 수 있다.
	- 결국 서버를 재기동할 필요가 있다.

문제 7. 32bit 운영체제와 64bit 운영체제의 차이점을 작성하시오.

 - 운영체제 종류에 따라 수십 GB~수 TB까지도 지원 가능하다.
 - 대규모 작업 처리가 가능하며, 이로 인해 서버 및 고성능 시스템에 사용된다.
