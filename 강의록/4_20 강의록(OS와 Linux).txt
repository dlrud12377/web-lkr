 < 4/20 강의록 >

 < 운영체제 >
	- 하드웨어와 소프트웨어 기능을 사용자가 편리하게 사용할 수 있도록 돕는 '시스템 소프트웨어'이다.
	- 자원(cpu가 해야 하는 작업, 메모리의 양 등등)을 효율적으로 배분하는 '총괄 관리자' 역할을 함
	- 목적에 따라 어떤 운영체제의 종류와 버전을 선택할지 신중히 고민해야 한다.
	- 서버 개발 시에는 Linux, 사용자 전용 소프트웨어 개발 시에는 Windows를 많이 사용함
	- 애플 관련 앱 개발 시에는 MacOS 선택

 < 운영체제의 주요 기능과 목적 >

	1. 처리능력의 향상 : 한정된 시간 내에 많은 데이터를 처리할 수 있게 한다. 처리량이 낮으면 병목 현상이 발생한다.
	
	2. 응답시간 단축 : 느리면 사용자 경험(UX)에 영향을 주고 서비스 이탈이 발생한다.

	3. 신뢰도 향상 : 시스템이 오류없이 안정적으로 동작하고, 오류 상황 시 전체 시스템이 무너지지 않도록 보호/관리

	4. 인터페이스 제공 : 사용자와 컴퓨터가 서로 소통할 수 있게 해주는 접점을 제공함
			- CLI(명령어 기반) -> 터미널
			- GUI(그래픽 기반) -> Windows, MacOS

	5. 입출력 관리 : 입력 장치와 출력 장치가 정상적으로 동작하도록 관리

	6. 프로그램 및 사용자 보호 : 프로그램끼리 서로 함부로 침범하지 못하게 하고, 사용자 데이터도 안전하게 지키는 기능
	7. 주기억 장치(RAM) 관리 : 필요한 프로그램에 메모리를 할당하고, 사용이 끝나면 회수한다.

	8. CPU 관리 : 운영체제가 CPU를 어떤 프로그램에 먼저 사용할 지 결정

	9. 파일 관리 : 파일을 만들고, 저장하고, 삭제하고 찾고, 보호하는 기능

	10. 명령어 해석 및 실행 : 사용자가 입력한 명령어를 해석하고 실행하는 기능



 < 관리자 권한 >
	- 운영체제 전체를 제어할 수 있는 권한
	- 시스템 설정을 변경할 수 있다.
	- 윈도우 기준 : 우클릭 -> 관리자 권한으로 실행하기
	- 특정 폴더에 접근
	- 관리자 권한이 없어서 설치할 수 없는 것들을 설치할 수 있다.

< 일반 권한 >
	- 개인 작업만 가능
	- 시스템에 영향을 주지 않음

 < 메모리 누수 >
	- 사용이 끝난 메모리를 해제하지 못하고 계속 들고 있는 상태
	- 컵에 물을 따라서 마시는데 남아있고, 남아있는 물에 물을 또 따르면 넘치는 것처럼
	- 메모리가 해제가 안되면 결국 프로그램이 터짐
	- C언어 프로그램의 경우 개발자가 직접 메모리 회수 및 할당 가능
		ㄴ 어렵긴 하지만 효율적으로 프로그램을 만들 수 있음
	- JAVA의 경우 JVM 내에 GC(Garbage Collector)가 있음 -> 객체가 사용이 안되는 것 같으면 메모리를 회수함.

 < CPU >
	- CPU는 한 번에 하나의 작업만 실행함
		-> 엄청 빠르게 번갈아 실행하기 때문에 동시에 실행되는 것처럼 보임

 < 코어 >
	- CPU 안에 있는 실제 계산하는 장치
	- 하나의 코어 -> 하나의 "작업 처리 유닛"

 < 스레드 >
	- 프로그램 안에서 실행되는 작업 흐름
	- CPU가 실제로 처리하는 단위

 < 로그 >
	- 프로그램이 실행되면서 남기는 기록
	- 문제 해결의 가장 중요한 단서가 됨 (운전 시 블랙박스의 역할)

 < 오픈소스 >
	- 소스코드가 공개되어있는 소프트웨어
	- 누구나 자유롭게 열람, 수정, 배포할 수 있다.
	< 오픈소스 사용의 장점 >
		1. 비용 절감 : 대부분 무료, 기업에서도 적극적으로 활용
		2. 빠른 개발 : 로그인 기능 직접 구현하기보다 라이브러리를 쓰는 게 좋다.
			-> 개발 속도가 폭발적으로 증가함
		3. 검증된 코드 : 많은 개발자가 사용하고, 버그를 빠르게 발견하고, 안정성이 높음
		4. 커뮤니티 지원
			- 검색하면 웬만하면 해결방법이 있음
			- 문서와 예제가 풍부함

 < 라이브러리 >
	- 클래스나 인터페이스의 묶음
		ㄴ 필드, 메서드를 정의해놓을 수 있다.
	- 다른 프로젝트에서 라이브러리를 import하여 필드나 메서드를 사용할 수 있다. 

 < 임베디드 >
	- 특정 기능을 수행하기 위해 기기 안에 내장된 컴퓨터 시스템
		ex. 전자레인지, 세탁기, 자동차, 티비, 에어컨 등등

wsl(Windows SubSystem for Linux)
윈도우 안에서 리눅스 환경을 실행할 수 있게 해주는 기능
윈도우를 그대로 쓰면서도 bask, ls, pwd, apt, git와 같은 리눅스 명령어와 도구를 사용할 수 있다.
전통적인 가상머신이나 듀얼부팅 없이 Windows에서 GNU/Linux 환경을 직접 실행할 수 있다.

가상머신보다 가볍고 편하기 때문에 사용을 한다.

wsl을 통해 리눅스를 설치하게 되면 Linux 커널을 기반으로 만들어진 Ubuntu가 설치가 된다.

wsl --install : 윈도우용 리눅스 설치하기

wsl --install -d Ubuntu : 우분투 설치하기

sudo(Superuser Do)
 - 리눅스에서 관리자 권한으로 실행해라 라는 뜻

우분투에서는 일반 사용자가 아무 프로그램이나 시스템에 설치하거나 바꾸지 못하게 막아둔다.
 - 실수로 시스템이 망가지는 것을 방지
 - 보안 강화
 - 중요한 파일 보호

 시스템 전체에 영향을 주는 명령어는 보통 sudo가 필요하다.

 apt
 우분투에서 프로그램을 관리하는 도구
정확히는 패키지 관리자 라고 부른다.
 - 프로그램
 - 라이브러리
 - 설치파일의 묶음
 - 업데이트 파일

 윈도우에서는 인터넷에 접속하여 .exe파일을 직접 다운로드해서 설치한다.

우분투는 apt를 통해 설치를 한다.
update : 패키지 목록 정보를 최신으로 갱신하는 것
sudo apt update : 관리자 권한으로 우분투 관리 도구를 최신으로 업데이트함. 이 때 인터넷이 연결되어 있어야 하는데

<이유>
설치 목록이 오래됐을 수 있기 때문
설치 오류가 날 수도 있음
구버전을 설치하게 될 수도 있음

저장소에서 정보를 받아와야 하므로 인터넷이 연결되어 있어야 함

시스템 패키지 정보에 영향을 주기 때문에 보통 sudo를 붙여야 한다.
