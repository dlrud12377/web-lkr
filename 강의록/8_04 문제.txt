문제 1. 테스트 범위 및 대상 정의
시나리오

A 쇼핑몰은 고객이 주문하면 주문 정보가 연계 서버를 거쳐 ERP 시스템으로 전달되는 구조이다.

현재 개발자는 연계 모듈 테스트를 수행하려고 하지만, ERP DB만 테스트하면 충분하다고 주장하고 있다.

프로젝트 책임자는 송신 시스템부터 수신 시스템까지 전체 연계 과정을 테스트해야 한다고 설명하였다.

조건

다음 내용을 모두 포함하여 작성하시오.

테스트 범위를 작성하시오.
 - 수신 및 송신 시스템 전역

테스트 대상 5가지를 작성하시오.
 - ERP의 수신 DB
 - 쇼핑몰의 송신 DB
 - 로그 테이블과 오류 테이블
 - 연계 서버 또는 어댑터
 - 인터페이스 테이블 또는 파일

ERP DB만 테스트해서는 안 되는 이유를 작성하시오.
 - ERP DB만을 테스트 대상으로 삼아 정상적인 결과가 나오더라도, 연계 과정에서 새로운 예외 상황이 생길 수 있기 때문에 전체 연계 과정을 테스트해야 한다.

 - ERP DB만 테스트하면 최종 데이터의 저장 여부만 확인할 수 있다. 쇼핑몰 송신DB에서 데이터가 정상적으로 추출되었는지, 연계 서버가 데이터를 정상적으로 전달하거나 변환했는지, 인터페이스 테이블 또는 파일이 올바르게 생성되었는지 확인할 수 없다.

따라서 데이터가 어느 구간에서 누락되거나 변형되었는지 정확하게 파악하기 위해서는 송신 시스템부터 수신시스템까지 전체 연계 과정을 테스트해야 한다.

코드 변환 오류가 발생한다.

 - 송신 DB와 수신 DB의 테이블값 비교 : 예약번호, 환자명, 예약 날짜, 담당 의사 등의 데이터 값이 변경되지 않고 정확하게 전달되었는지 확인하여 데이터의 무결성을 검증한다.

문제 4. 테스트 환경 구축
시나리오

회사는 테스트 비용을 줄이기 위해 운영 DB를 그대로 사용하여 연계 모듈 테스트를 수행하려고 한다.

또한 방화벽 설정도 확인하지 않은 상태에서 테스트를 시작하였다.

조건

다음 내용을 모두 포함하여 작성하시오.

운영 DB를 테스트에 사용하면 안 되는 이유를 작성하시오.
 - 운영 DB를 테스트에 직접적으로 사용하면 테스트 조작 과정에서 원본 데이터의 소실 및 오염의 가능성이 생긴다.
(테스트 과정에서 데이터가 수정, 삭제, 중복 등록 되면 실제 업무에 피해가 발생할 수 있다. 또한 비정상 데이터, 중복 PK, 필수값 누락 등의 오류 상황을 운영 DB에서 테스트하면 운영 서비스가 중단되거나 데이터의 무결성이 훼손될 수 있다.)
따라서 원본 데이터에서 복제된 테스트용 DB 및 테이블을 따로 두어 별개의 DB로 테스트를 진행해야 한다.

테스트 환경 구축 시 준비해야 하는 항목을 6가지 작성하시오.

 - 컴퓨터 설치
 - 시험 프로그램 설치
 - 인터넷 연결
 - 로그인 계정 준비
 - 저장 공간 준비
 - 연계 서버 설정 및 어댑터 설치
 - 테스트용 DB, 테이블 생성
 - 테스트용 파일 경로 설정
 - 네트워크 방화벽 및 포트 설정
 - 인증 및 보안 설정
 - 로그 및 모니터링 환경 설정

테스트 환경은 운영 환경과 어떻게 구성해야 하는지 작성하시오.
 - 테스트 환경은 가능한 한 운영 환경과 유사하게 구성해야 한다.
 - 운영 체제, DBMS, 네트워크, 서버 사양, 보안 정책, 연계 솔루션 버전, 데이터 규모를 운영 환경과 비슷하게 구성한다.
 - 환경 차이가 크면 테스트에서는 정상적으로 동작했지만 운영 환경에서는 성능 저하나 호환성 오류가 발생할 수 있다.

문제 5. 정상 시나리오와 비정상 시나리오
시나리오

회원 정보를 다른 시스템으로 전송하는 연계 모듈을 테스트하려고 한다.

프로젝트 팀장은 정상적인 데이터뿐 아니라 오류 상황도 반드시 테스트하도록 지시하였다.

조건

다음 내용을 모두 포함하여 작성하시오.

정상 시나리오 테스트 4가지를 작성하시오.
- 정상 데이터 전송(정상적인 회원 데이터가 수신 시스템으로 전송되는지 확인)
- 정상 코드 매핑(회원 코드가 약속된 코드로 정상적으로 매핑되는지 확인)
- 정상 DB 반영(수신된 회원 데이터가 수신 DB에 정상적으로 반영되는지 확인)
- 정상 로그 기록(전송 시작 시간, 완료 시간, 처리 결과가 로그에 정상적으로 기록되는지 확인)

비정상 시나리오 테스트 6가지를 작성하시오.
 - DB LOCK을 발생시켜 대기, 오류 기록 또는 재전송 여부를 확인
 - 연계 서버 중지 시 오류 로그가 남는지, 관리자에게 알림이 가는지, 서버가 다시 시작되면 재전송되는지 확인
 - 데이터 길이 초과 : 허용된 길이를 초과한느 데이터를 전송하여 오류 처리 여부를 확인
 - 등록되지 않은 코드 전송 : 약속되지 않은 코드를 전송했을 때 시스템이 오류를 일으키는지 확인한다
 - 중복 PK 데이터 전송 시 중복 오류가 발생하는지. 이에 대한 로그가 기록되는지, 반대로 필수 값을 누락하여 오류 처리가 어떻게 되는지도 확인
 - 대용량 데이터 전송 : 100만건 또는 1000만건 데이터를 전송하여 처리 속도, 메모리 사용량, CPU 사용량 등을 확인

비정상 시나리오 테스트가 필요한 이유를 작성하시오.
 - 실제 운영 중 발생할 수 있는 장애와 잘못된 데이터에 시스템이 정상적으로 대응하는지 확인하기 위해 필요하다.
 - 오류가 발생했을 때 로그 기록, 오류 코드 반환, 관리자 알림, 재처리, 롤백 등이 제대로 수행되지 않으면 데이터가 누락되거나 중복되고 업무가 중단될 수 있다.

	ㄴ 테스트 작업이 실제 운영 시스템에 영향을 줄 수 있으며, 운영 권한이 노출될 수 있다.
 - 접근 권한이 제한되지 않은 문제
	ㄴ 허가되지 않은 사용자가 테스트에 접근할 수 있다
	-> 업무와 역할에 따라 접근 권한을 제한해야 한다.
 - 데이터 및 전송 구간이 암호화되지 않음
	 -> HTTPS의 TLS, VPN, SSH 등을 사용하여 전송 구간 암호화 및 복호화





개인정보 마스킹과 데이터 익명화의 차이를 작성하시오.
개인정보 마스킹은 개인정보의 민감한 부분을 DB 프로시저나 함수를 통해 다른 특수문자 등으로 대체하여 데이터를 못 보도록 하는 방식이고, 데이터 익명화는 마스킹을 포함하여 개인 식별 정보를 지우거나 바꾸어 어떤 사람인지 아예 알 수 없게 만드는 방식이다.
