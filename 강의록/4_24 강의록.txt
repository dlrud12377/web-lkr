 < 스키마 >
 1. 정의
	- 데이터베이스의 구조, 테이블, 뷰, 제약 조건 등과 같은 메타데이터를 정의한 것으로, 데이터를 저장하고 관리하기 위한 전체적인 설계도 또는 컨테이너를 의미함(데이터를 어떻게 저장할 지 구조를 정의)
	- MySQL에서는 '스키마'와 '데이터베이스'가 거의 같은 의미로 사용

 2. 특징
	- 데이터 구조 정의 : 스키마는 테이블의 열(컬럼)에 어떤 종류의 데이터가 들어갈지, 데이터의 형식과 제약 조건은 무엇인지 등 데이터의 구조를 정의합니다.
	- 청사진 역할 : 데이터베이스 전체를 구성하는 테이블, 뷰, 프로시저, 트리거 등의 집합을 포함하며, 데이터가 어떻게 구성되고 저장될지에 대한 청사진 역할을 합니다.
	- 사용자 관리 : 스키마는 사용자가 생성하고 관리할 수 있으며, 사용자별로 데이터를 구분하고 접근 권한을 관리하는 데 사용될 수 있습니다.
	- 엑셀에서 각 열의 제목과 데이터 형식을 정해놓는 것과 유사하며, 사용자가 의도한 방식으로 데이터가 입력되도록 안내하는 규칙을 제공합니다.

 3. 스키마의 종류
	- 외부 스키마: 사용자가 데이터베이스를 어떻게 인식하는지에 대한 뷰(view)를 정의
		- 사용자마다 다르게 보일 수 있음
		- 필요한 데이터만 보여줌
		- 보안에 중요함
	- 개념 스키마: 데이터베이스 전체 구조를 논리적으로 정의하며, 데이터 간의 관계와 보안 등을 포함한다.
		- 모든 데이터의 구조를 정의
		- 테이블, 관계, 제약조건 포함 -> 보안과 관계를 케어함
		- DB 설계의 중심
	- 내부 스키마: 데이터가 물리적 저장 장치에 어떻게 저장되는지(데이터 타입, 저장 위치 등)를 정의한다.
		- 데이터가 실제로 저장되는 방식
		- 디스크에 어떻게 저장되는지 정의
		- 인덱스, 파일 구조 포함
		- 성능과 관련있음 


 < SQL문 >
  1. 정의 및 특징
	- 구조화된 질의언어(Structured Query Language)의 약자로 DBMS 상에서 데이터를 읽고 쓰고 삭제하는 등 데이터를 관리하기 위한 일종의 프로그램 언어이다.
	- RDBMS의 표준 언어로 SQL을 채택했고, 표준 SQL문만 학습하면 오라클은 물론 MSSQL, DB2등 여러 DBMS에서 동일하게 사용할 수 있다는 뜻이다.
	- 물론 DBMS별로 독특한 기능이 있지만, 다른 프로그래밍 언어에 비해 그 차이는 미미하다.
	- SQL문장은 대소문자를 구별하지 않는다.
	- 한줄 또는 여러줄에 걸쳐 입력하는 것이 가능
	- SQL	문장의 끝은 세미콜론(;)으로 맺어야 한다.

 2. SQL문장의 종류
	1. DDL(Data Definition Language) : 데이터 정의어
    	- 데이터베이스 객체를 관리하는 언어이다.
	2. DML(Data Manipulation Language) : 데이터 조작어
   	 - 데이터 삽입, 조회,삭제, 갱신 등 실제로 데이터를 조작하는 언어이다.
   	 - 개발자 입장에서 가장 많이 사용하는 SQL이다.
	3. DCL(Data Controll Language) : 데이터 제어어 ( 데이터 관련 권한 제어 )
    	- grant, revoke등의 키워드를 가지는 문장
	4. TCL(Transaction Controll Language) : 트랜잭션 제어어
    	- commit, rollback, savepoint

 SQL을 작성하고 실행하게 되면 -> 임시로 반영이 된다.(결과를 확인할 수 있음)
 -> 마음에 들면 COMMIT / 마음에 안들면 ROLLBACK(주의할 점은 COMMIT하고 나서 롤백은 불가)


3. DDL(Data Definition Language) : 데이터 정의어
	- 데이터베이스 객체를 생성, 삭제, 변경하는 언어이다.
  	1. CREATE : 테이블이나 인덱스, 뷰 등 데이터베이스 객체를 생성한다.
    	2. DROP : 생성된 데이터베이스 객체를 영구히 삭제
    	3. ALTER : 이미 생성된 데이터 베이스 객체를 수정
    	4. TRUNCATE : 테이블의 데이터를 통째로 삭제

 < 데이터베이스의 생성 >
- 테이블, 뷰, 인덱스,저장프로시저 등 데이터베이스 오브젝트를 담는 논리적 네임스페이스이다.
- MySQL에서는 데이터베이스와 스키마 라는 용어를 동의어로 사용하나, 다른 RDBMS에서는 구분되는 점이 있으니 문맥에 따라 주의해야 한다.

 1. 주의사항
	1. 이름 규칙 : 소문자, 밑줄(`_`) 사용을 권장하고, 공백 금지
	2. 권한 정책 : `root` 로 직접 서비스하지 않도록 최소 권한 원칙을 계획한다.	
	3. 운영/개발 분리 : 개발용 DB, 테스트용 DB,운영용 DB 구분계획을 세운다.
	4. 백업/복구 정책 : 정기 백업 주기, 보관 기간, 복구 절차를 미리 정의한다.

 2. 데이터베이스 생성 코드
CREATE DATABASE IF NOT EXISTS academy_db
CHARACTER SET = utf8mb4
COLLATE = utf8mb4_unicode_ci

`CREATE DATABASE`

- 새로운 데이터베이스(스키마)를 생성하라는 명령이다

`IF NOT EXISTS`

- 같은 이름(academy_db)을 가진 데이터베이스가 이미 존재하면 **오류 내지 않고 그냥 무시**한다
- 이미 있으면 건너뛰고, 없을 때만 생성하라

`academy_db`

- 생성하려는 데이터베이스의 이름이다.
- 보통 소문자 + 밑줄(`_`) 규칙을 많이 사용한다

`CHARACTER SET = utf8mb4`

- 이 데이터베이스에서 **문자를 저장할 기본 문자셋(Encoding)** 을 지정한다
- `utf8mb4`는 MySQL에서 **가장 안전한 유니코드 문자셋**이다.
    - 한글
    - 모든 외국어 문자
    - 이모지(😀, 👍)

`COLLATE = utf8mb4_unicode_ci`

- 정렬(ORDER BY)과 비교(대소문자 구분 여부 등)의 기준을 설정한다.
- `unicode_ci`의 특징:
    - `ci` = Case Insensitive (대소문자 구분 안함)
        
        `abc = ABC`로 처리된다.
        
    - 국제 언어 지원에 적합하다.

4. 제약조건
 - 제약조건 : 테이블에 문제가 되는 결함이 있는 데이터가 입력되지 않도록 미리 지정해둔 조건
 - 제약조건은 테이블을 생성할 때 함께 설정할 수 있고, 추후에 생성하거나 변경할 수도 있음

NOT NULL : 해당 컬럼에는 반드시 데이터를 입력해야 함
UNIQUE : 해당 컬럼은 유일한 값, 즉 중복된 값을 허용하지 않음
PRIMARY KEY(기본키) : UNIQUE와 NOT NULL을 둘다 가진 제약조건.
FOREIGN KEY(외래키) : 외부 테이블의 PK 값을 참조하여 현재 제약조건을 걸 테이블에 제약을 걸어준다.
