문제 1. 테스트 단계 판단

온라인 쇼핑몰의 주문 기능을 개발하고 있다.

개발자는 다음 메서드가 상품 가격과 주문 수량을 이용하여 정확한 주문 금액을 계산하는지 확인하려고 한다.

public int calculateTotalPrice(int price, int count) {
    return price * count;
}

테스트할 때 데이터베이스, Controller, 다른 Service와의 연결은 사용하지 않고 해당 메서드만 독립적으로 검증하려고 한다.

문제

위 상황에서 수행해야 할 테스트 종류를 작성하고, 그렇게 판단한 이유를 2가지 이상 서술하시오.

 - 단위 테스트
 1. 해당 메서드만 독립적으로 검증해야 하기 때문에
 2. 메서드와 같은 작은 단위의 기능이 동작하는지, 그리고 그 기능이 논리적인 오류가 없는지를 확인해야 하기 때문에

 - 프로그램 전체가 아닌 계산 로직 하나를 대상으로 검증하기 때문이다.
 - 하나의 작은 기능 단위를 독립적으로 테스트하기 때문이다.

사용자 요청
   ↓
Controller
   ↓
Service
   ↓
DAO
   ↓
Database

분석 결과 Service에서 DAO로 회원번호를 전달하는 과정에 문제가 있을 가능성이 있다고 판단하였다.

 1. 컨트롤러가 Service의 올바른 메서드를 호출하는지
 2. Service가 DAO에 올바른 회원번호을 전달하는지
 3. DAO가 전달받은 값을 이용하여 올바른 SQL을 수행하는지 확인

회원의 나이는 14세 이상 100세 이하인 경우에만 가입할 수 있다.

학생은 이 요구사항에서 경계 부분에 오류가 발생할 가능성이 있다고 판단하여 경곗값 분석을 적용하려고 한다.

문제 6. 구문 커버리지와 결정 커버리지 판단

다음 코드를 테스트한다.

public int calculateDiscount(int price) {

    int discount = 0;

    if (price >= 50000) {
        discount = 5000;
    }

    return price - discount;
}

다음 테스트 하나만 수행하였다.

입력 : 60000
결과 : 55000
문제

위 테스트 결과에 대해 다음 두 가지를 각각 판단하고 이유를 작성하시오.

구문 커버리지는 100%인가?
 - 100%이다. 조건이 참이기 때문에 조건문 내 조건식이 실행되었고, 따라서 모든 구분이 전부 실행되었기 때문이다.

결정 커버리지는 100%인가?
 - 아니다. 조건식이 참일 때의 흐름만 진행이 되었으므로 거짓인 케이스 데이터가 없어 결정 커버리지가 100%가 나오지 않는다.

결정 커버리지 100%가 아니라면 추가할 테스트 데이터를 하나 작성하시오.
- 45000(50000 미만)

버튼을 연속 클릭했을 때 중복 데이터 생성

비정상적으로 큰 수량 입력하기

	- 허용되지 않은 입력에 대해 오류 처리 및 입력 제한이 정상적으로 수행되는지 확인한다.
