 1. 제어 역전(Inversion of Control) - 제어 자동화
 - 우리가 직접 객체를 만드는 것이 아니라, 스프링이 객체를 만들고 필요한 곳에 주입해주는것

 - 순서
	1. 스프링이 객체로 만들도록 클래스에 @Component 어노테이션을 붙인다.

	@Component
	public class Engine{
		public void start() {Code;}
	}

	@Component
	public class Car{
		Engine engine;

		engine.start();
	}

	2. 프로젝트를 실행하면 필드로 사용되는 곳에 만들어 놨던 객체를 주입하여 메서드를 사용할 수 있도록 해준다.

 2. 의존성 주입
 (1). 필드 직접 주입
	- @Autowired 사용
 (2). setter의 매개변수 자리에 주입
 (3). 생성자의 매개변수 자리에 주입

 3. gradle
 - 다양한 프로그래밍 언어를 지원하는 빌드 자동화 도구
 - 의존성 관리, 테스트 실행, 배포, 패키징 등의 빌드 작업을 자동화하며, 유연성과 확장성을 중시한다.

 - 필요한 라이브러리가 있으면 build.gradle 파일의 dependencies 부분에 링크를 붙여넣으면 스프링이 자동으로 다운받는다.
 	ㄴ mvn repository에서 링크를 복사해온다.

 4. 스프링 프로젝트 : 대개 "레이어드 아키텍처 패턴"으로 이루어져있다.

	표현 계층 : 클래스 이름 뒤에 Controller를 많이 붙인다.
	 - http 요청 처리
	 - 응답 처리

	비즈니스 계층 : 클래스 이름 뒤에 Service를 많이 붙인다.
	 - 실제 업무를 수행

	영속 계층 : 클래스 or 인터페이스 이름 뒤에 Repository를 많이 붙인다.
	 - 데이터베이스와 직접 통신하는 계층
	자신과 맞닿아있는 계층으로만 이동이 가능하다.

5. 컨트롤러
 - 클라이언트의 HTTP 요청을 받아서 적절한 기능을 실행하고, 처리 결과를 HTTP 응답으로 반환하는 계층이다.

	1. 사용자가 브라우저, 모바일 앱, Postman 같은 프로그램을 통해 서버에 요청을 한다. (URL을 적어서 요청)

	요청방식 : GET
	요청 주소 : /users/1
	전달 데이터 : 1

	2. @RestController : 해당 클래스가 컨트롤러로 취급되기 위한 어노테이션
		ㄴ @Controller + @ResponseBody를 합친 어노테이션
		@ResponseBody : 응답결과를 데이터로 주는 어노테이션

	** 어노테이션에도 상속 관계(정확히 말하면 meta annotation 계층 - 완전한 포함 관계)가 있다.


	@Component(Grandparent)
		│
	@Controller(Parent)
		│
	@RestController(Child)
		│
	@Service
		│
	@Repository


	3. Mapping Annotation
		@RequestMapping("경로(/users)") : 클래스에 붙인다.
		@GetMapping("경로") : 메서드에 붙인다.
	 - 클라이언트의 HTTP 요청을 Controller 메서드와 연결하는 역할을 한다.

	 - 클래스 주소 + 메서드 주소가 합쳐지게 된다.

	3. @PathVariable
	 - 주소의 일부분을 변수로 하여 데이터를 가져오는 어노테이션

	http://localhost:10000/users/10

	@GetMapping("users/{id}")
	public String findUser(@PathVariable("id") Long id) {
	
	}

	만약 getmapping의 {} 안에 들어있는 변수명과 매개변수명(Long "id")가 같으면 생략 가능

	@GetMapping("users/{id}")
	public String findUser(@PathVariable Long id) {
	
	}

	4. @RequestParam
	 - 검색 조건이나 옵션에서 사용하는 것이 REST API 설계의 관례
	URL의 쿼리스트링에 포함된 값을 받아오는 어노테이션
	http://localhost:10000/users?name=홍길동

	5. DTO VS 엔티티
	DTO : 각 계층간 데이터를 주고받기 위한 객체
	엔티티 : 데이터베이스 테이블을 표현하는 객체

Q. 이름 인사 출력 프로그램
사용자가 화면의 이름을 입력하고 버튼을 누르면, JS의 fetch()를 이용하여 Springboot의 Controller로 이름을 전송한다.
Controller는 전달받은 이름을 Service로 전달하고, Service는 인사 문장을 생성하여 Controller로 반환한다.
Controller는 그 결과를 다시 브라우저에 반환한다.

controller : HelloController
 - public String hello();

service : HelloService
 - public String getHelloMessage(String name)
 - 반환값은 안녕하세요, xxx님! (이름은 name을 매개변수로 받아 출력)

요청주소 GET /api/hello?name=xxx


CORS(Cross-Origin Resource Sharing)
교차 출처 리소스 공유

출처(Origin)
 - 프로토콜, 호스트주소, 포트번호까지 모두 합친 주소를 의미한다.
 - 서버의 위치를 찾아가기 위해 필요한 가장 기본적인 것들을 합쳐놓은 것

동일 출처 정책(Same-Origin Policy)
 - 브라우저는 기본적으로 보안을 위해 동일 출처 정책이라는 규칙을  따른다.
 - 같은 출처에서 로드된 웹사이트만 서로 데이터를 주고받을 수 있다.
 - 다른 출처에서 데이터를 요청하는 것을 제한하는 정책
 - 이 정책은 보안을 위해 존재하는데, 악의적인 웹사이트가 사용자의 브라우저를 이용해 다른 출처에서 데이터를 가져오지 못하게 막는 역할을 한다.

교육 과정 수강생 등록 및 조회 프로그램

HTML과 JavaScript를 사용하여 수강생 정보를 입력하고, Spring Boot 서버에 저장된 수강생 목록을 조회하는 프로그램을 작성합니다.

프론트엔드 파일은 Spring Boot 프로젝트 내부에 저장하지 않고 별도의 폴더에서 실행합니다.

프론트엔드
HTML + JavaScript
      ↓ fetch()
Spring Boot 서버
Controller → Service → ArrayList

데이터베이스는 사용하지 않으며, 입력받은 데이터는 Service 클래스의 ArrayList에 저장합니다.

프로그램 기능

프로그램은 다음 두 가지 기능을 제공합니다.

기능 1. 수강생 목록 조회
서버의 ArrayList에 저장된 모든 수강생을 조회하여 HTML 표에 출력합니다.

기능 2. 수강생 등록
사용자가 입력한 다음 정보를 서버로 전송합니다.

이름
과정명
이메일

서버는 전달받은 정보를 ArrayList에 저장하고 저장 결과를 반환합니다.
