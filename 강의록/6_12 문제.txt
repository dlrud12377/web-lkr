[Q10] UI 프로토타입 검토 단계에서 수행하는 '사용성 테스트(Usability Testing)'의 일반적인 진행 프로세스를 서술하시오.

 - 테스트 목표와 시나리오를 정의한 후, 타겟 사용자를 모집한다. 사용자에게 특정 과제를 수행하도록 요청하고 그 과정을 관찰 및 녹화한다. 태스크 완료 후 인터뷰를 통해 불편사항을 수집하고, 분석 결과를 설계에 반영한다.

1. 일반 사용자, 전문가, 개발자 등 적절한 테스트 대상자를 선정한다.
	- 초보 사용자, 실무자, 접근성 요구자 등 사용자 유형을 정의한다.
	- 사용자 유형별 테스트 수행 방식을 정의한다
	- 사용자 데이터 수집 및 분석을 위해 사전 동의 절차를 정의한다
2. 유스케이스 기반 테스트를 수행한다
	- 핵심 시나리오를 작성한다
	- 테스트 환경을 구축한다
	- 과제별 수행 시간, 성공 여부, 오류 여부 등을 기록한다
3. 사용자의 마우스 이동, 머뭇거림, 잘못된 클릭 등에 대한 기록을 확인한다
	- 행동 기록 도구를 선정한다
	- 버튼 클릭 오류, 빈 화면 클릭 등 비정상 상호작용을 표시한다
	- 머뭇거린 시간, 클릭 순서, 반복 행동 등을 분석한다
4. 사용성, 디자인 만족도 등 평가 항목별로 사용자 의견을 수집한다
	- 사용자 설문지나 면담 문항을 작성한다
	- 평가 점수와 자유 의견을 정리한다
	- 반복 제안이나 긍정/부정 의견을 분류하고 요약한다
5. 테스트 결과를 취합하여 주요 문제점과 개선 제안 내용을 문서로 작성한다
	- 문제 발생 빈도와 심각도에 따라 분류한다
	- 주관적인 불만과 실제 오류가 일치하는지 비교 분석한다
	- 개발에 적용할 수 있는 개선안을 도출하고 우선순위를 정리한다

 - 사용자 페르소나는 대표 사용자를 가상의 인물로 정의한 것으로, 사용자의 목적에 따라 프로그램이 어떻게 진행되는지 설정할 수 있도록 시나리오를 짤 수 있다.

답 : 페르소나는 타겟 사용자의 대표적인 특징과 행동 양식을 정의한 가상의 인물이다. 페르소나가 명확하면 해당 사용자의 숙련도와 목적에 맞추어 불필요한 단계를 줄이거나, 안내를 강화하는 등 최적의 동선을 설계할 수 있다.

답 : 사용자가 원하는 기능과 필요한 제약조건이 무엇인지 명확히 정의되어야만, 이를 바탕으로 구조를 짜고 프로토타입을 그리거나 상세 설계를 진행할 수 있기 때문이다.

 - 프로토타입을 제작하면 사용자가 요구사항의 반영 상태를 바로 확인하고 개발자에게 피드백을 줄 수 있기 때문에, 개발자와 사용자의 요구사항 목록을 일치시키는 역할을 하게 된다.

답 : 텍스트로만 된 요구사항을 눈으로 볼 수 있는 실제 화면 형태로 보여줌으로써, 서로 생각하는 결과물이 일치하는지 눈으로 확인하고 오해를 줄여주는 의사소통 도구 역할을 한다.



[Q19] 'UI 상세 설계' 단계에서 단순히 화면 그림만 그리지 않고, 각 컴포넌트의 작동 규칙이나 제약조건을 문서로 명세해야 하는 이유를 서술하시오.

 - 화면 그림으로만 그리면 협업 과정에서 해당 컴포넌트가 어떤 역할을 수행하고, 어떠한 원리로 작동되는지 설계자 이외에 나머지가 직관적으로 알 수 없다. 따라서 작동 규칙과 제약조건을 문서로 명시하여 해당 컴포넌트가 어떤 디테일을 가지고 있는지 공유해야 한다.

답 : 그림만 있으면 버튼을 눌렀을 때 어떤 데이터가 어떻게 움직이는지, 오류가 났을 때 어떤 메시지가 뜨는지 개발자가 알 수 없으므로, 정확한 프로그램 구현을 위해 세부 규칙을 텍스트로 명시해야 한다.
