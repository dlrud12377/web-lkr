프레임워크
 - 기본적인 구조가 마련이 되어있는 일종의 프로그래밍 재료

빌드 툴
gradle : groovy 기반의 의존성 관리 툴
	ㄴ build.gradle
maven : XML 기반의 빌드 및 의존성 관리 도구
	ㄴ pom.xml

프로젝트의 기본적인 구조
 - 레이어드 아키텍쳐 : 계층으로 나눈다.

표현계층 : Controller
	ㄴ HTTP 요청, HTTP 응답

비즈니스 계층 : Service
	ㄴ 비즈니스 로직을 실행
영속 계층 : Repository
	ㄴ 데이터베이스와 관련된 처리(CRUD)

DTO : 계층간 이동할 때 데이터를 담는 객체

ORM(Object Relation Mapping) : Java 객체와 관계형 데이터베이스 테이블을 연결해주는 기술
 - ORM이 없으면 .JDBC를 이용해서 코드를 직접 다 작성해야 함
 - ORM을 사용하면 SQL보다는 객체 중심으로 데이터베이스를 다룰 수 있다.

Entity
 - 테이블과 1:1로 매칭되는 클래스
 - @Entity(Entity Annotation)을 붙여야 Entity로 취급을 한다.
  - Entity 클래스로 만든 객체 -> 테이블의 1개의 행에 해당한다.

SQL Mapper
 - SQL을 개발자가 직접 작성하는 프레임워크

MyBatis
  - 개발자가 SQL을 직접 작성하고, 그 SQL의 실행 결과를 자바 객체에 연결해 주는 역할을 한다.

복잡한 SQL 제어 시
ORM : 상대적으로 불편할 수 있다.
SQL MAPPER : 직접 SQL을 작성하기 때문에 상대적으로 자유로움


실제 서비스는 많은 사람들이 로그인을 해서 사용하기 때문에 인증 매커니즘을 구현을 해야 한다.

인증
 - 사용자가 누구인지 확인하는 과정
 - 사용자 아이디와 비밀번호
 - 다중 요소 인증(sms, email)

인가
 - 사용자가 인증된 후에, 그 사용자가 무엇을 할 수 있는지 결정하는 과정
 - 특정 자원이나 기능에 접근할 수 있는 권한을 부여하는 절차

Basic 인증
 - Todo 프로그램은 로그인을 제외하면 상태를 유지해야 할 이유가 없다.
 - 상태가 없는 웹 어플리케이션에서 인증을 구현하는 방법은 모든 HTTP 요청에 아이디와 비밀번호를 같이 보내는 것이다.
 - 아이디와 비밀번호를 Base64 인코딩하여 HTTP 요청 헤더에 포함한 뒤 요청을 보낸다.
 - 서버는 데이터를 받아서 디코딩하여 사용자가 인증할 수 있는지 확인하고, 자격이 유효하면 요청한 자원에 접근을 허용한다.
