온라인 쇼핑몰 시스템의 통합 테스트를 수행하려고 한다. 프로젝트 일정상 아래 6개 기능 중 3개 기능만 우선적으로 테스트할 수 있다.

기능   현재 상황
A. 회원 프로필 사진 변경   최근 변경 없음, 장애 발생 시 영향 낮음
B. 카드 결제   외부 카드사 시스템과 연계되며 장애 발생 시 주문 불가
C. 상품 상세 조회   하루 평균 20만 회 사용
D. 공지사항 조회   최근 변경 없음, 사용 빈도 낮음
E. 주문 취소 및 환불   최근 프로그램이 수정되었으며 결제 시스템과 연계됨
F. 회사 소개 화면   정적 화면이며 업무 처리와 직접적인 관계 없음
요구사항

테스트 범위 선정 기준으로 다음 네 가지를 사용한다.

업무 중요도
장애 발생 시 영향
최근 변경 여부
외부 시스템 연계 또는 사용 빈도

위 조건을 적용하여 우선적으로 테스트해야 할 기능 3개를 선정하고, 각 기능을 선정한 이유를 주어진 선정 기준과 연결하여 서술하시오.

B. 카드 결제 : 최근 변경 여부는 없으나 외부 시스템 연계 및 장애 발생 시 영향력이 큼(장애가 발생하면 고객이 주문을 완료할 수 없어 업무 중요도와 장애 영향도가 높음)
C. 상품 상세 조회 : 사용 빈도가 높음
E. 주문 취소 및 환불 : 최근 프로그램이 수정된 이력이 있고, 결제 시스템과 연계되어 있어 외부 시스템 연계 위험도를 고려하여 먼저 테스트해야함

점검 항목   상태

문제 3. 테스트 시나리오와 테스트 케이스 설계

쇼핑몰의 카드 결제 업무 흐름은 다음과 같다.

로그인
 → 상품 선택
 → 주문서 작성
 → 카드 결제
 → 주문 데이터 저장
 → 주문 완료 화면

카드 결제 과정에서 다음 요구사항을 반드시 만족해야 한다.

정상 카드이면 결제가 승인되어야 한다.
카드사에서 승인을 거절하면 주문이 완료되어서는 안 된다.
결제가 성공하면 주문 정보가 DB에 저장되어야 한다.
결제 버튼을 여러 번 클릭하더라도 동일한 주문이 중복 결제되어서는 안 된다.
요구사항

위 업무 전체를 하나의 테스트 시나리오로 보고, 요구사항을 검증하기 위한 테스트 케이스 4개를 작성하시오.

각 테스트 케이스에는 반드시 다음 내용을 포함한다.

테스트 조건 → 예상 결과

정상 카드로 결제 시 -> 결제 승인 및 원래 화면으로 이동해야 한다.
카드사에서 승인 거절 시 -> 주문을 허가하지 않고 승인 거절 메시지를 띄움
정상 카드로 결제 성공 시 -> 결제 성공 후 DB에 해당 주문 정보 로그가 정상적으로 저장되어야 함
결제 버튼 여러 번 클릭 시 -> 하나의 주문에 대해 결제가 한 번만 처리되어야 하며 중복 결제 및 주문이 방지되어야 함

문제 4. 테스트 데이터 관리

쇼핑몰 주문 기능을 테스트하기 위해 개발자가 실제 운영 DB를 그대로 사용하려고 한다.

테스트 과정에서는 다음 작업을 수행한다.

테스트 회원의 개인정보 조회
상품 주문
주문 취소
결제
고객 문자 발송

현재 운영 DB에는 실제 고객의 이름, 전화번호, 주소 및 실제 주문 데이터가 저장되어 있다.

요구사항

운영 DB를 그대로 사용하여 테스트할 경우 발생할 수 있는 문제를 3가지 작성하고, 이를 방지하기 위한 테스트 데이터 관리 방법을 1가지 작성하시오.

운영 DB를 그대로 사용하여 테스트 시 발생할 수 있는 문제
 - 테스트 과정에서 실제 고객 데이터 변경이나 삭제가 발생할 수 있다.
 - 운영 DB에서 가져온 고객 이름, 전화번호, 주소 등의 실제 개인정보가 테스트 담당자에게 노출될 수 있다.
 - 테스트 주문과 같은 활동 및 동작이 실제 환경에 반영된다. (테스트 주문이 실제 매출에 반영, 테스트 문자가 실제 고객에게 발송 등)

이를 방지하기 위한 테스트 데이터 관리 방법
 - 별도의 테스트 데이터를 구성할 수 있다면 구성하는 것이 좋으나, 불가하다면 테스트 전 초기 데이터 상태 및 종료 후 데이터 복원 여부를 철저히 확인하고, 개인정보가 포함되어있다면 데이터 익명화 또는 마스킹 처리를 하여 개인정보 노출을 차단해야 한다.

문제 5. 기능 단위별 테스트 분석

회원가입 기능은 다음과 같이 동작한다.

회원가입 화면
      ↓
사용자 정보 입력
      ↓
서버에서 입력값 검증
      ↓
외부 휴대전화 인증 시스템 호출
      ↓
회원정보 DB 저장
      ↓
가입 완료 화면 출력

테스트 결과 다음 네 가지 문제가 발견되었다.

A. 가입 버튼을 눌러도 아무 동작을 하지 않는다.

B. 가입 완료 화면에는 정상적으로 표시되지만 DB의 전화번호가 잘못 저장된다.

C. 휴대전화 인증 요청 데이터의 전화번호 형식이 잘못되어 외부 인증 시스템에서 요청을 거부한다.

D. 생년월일을 이용한 나이 계산 결과가 실제 나이와 다르다.

요구사항

각 문제 A~D의 결함을 우선적으로 확인해야 할 기능 단위를 다음 중 하나로 각각 선정하고, 선정 이유를 서술하시오.

화면 모듈
데이터 입출력
인터페이스
서버 모듈

A는 화면 모듈에서 확인해야 한다. 버튼 동작 및 이벤트 확인이 필요하다.
B는 데이터 입출력을 확인해야 한다. DB에 실제 저장된 전화번호가 잘못되었기 때문이다.
C는 인터페이스를 확인해야 한다. 요청데이터 형식이 잘못되었으므로 시스템 간 인터페이스 테이블의 데이터 전달 및 변환 부분을 확인해야 한다.
D는 서버 모듈을 확인해야 한다. 나이를 계산하는 로직이 잘못되었으므로 서버 모듈에서 해당 로직을 찾아보아야 한다.

문제 6. 통합 테스트 결과 및 종료 판단

통합 테스트 100건을 수행한 결과 다음과 같은 결함이 남아 있다.

결함   내용
A   결제 버튼 색상이 화면 설계서와 다름
B   개인정보가 다른 사용자에게 노출됨
C   도움말 화면에 맞춤법 오류가 있음
D   카드 결제가 전혀 처리되지 않음

프로젝트 담당자가 일정이 부족하다는 이유로 통합 테스트를 종료하려고 한다.

요구사항

현재 통합 테스트를 종료할 수 있는지 판단하고, 종료를 막는 결함을 모두 선택하여 각각의 이유와 함께 서술하시오.
 - 종료할 수 없다.
 - B는 개인정보가 다른 사용자에게 노출되는 결함으로 보안 및 개인정보 보호에 중대한 영향을 미치므로 테스트를 종료할 수 없다.
 - D는 카드 결제가 전혀 처리되지 않는 결함으로 쇼핑몰의 핵심 업무인 결제가 수행되지 않기 때문에 테스트를 종료할 수 없다.
 - A,C의 경우는 기능 자체에는 문제가 되지 않으므로 영향도가 낮다.

 - 테스트 종료는 모든 결함이 제거되었는지만 보는 게 아니라 남아있는 결함의 중요도와 운영 위험을 고려하여 판단해야 한다.

문제 1. 결함 여부 판단 및 근거 작성

온라인 쇼핑몰의 회원가입 기능에 다음 요구사항이 정의되어 있다.

비밀번호는 8자 이상 입력해야 한다.
비밀번호가 8자 미만이면 "비밀번호는 8자 이상 입력해야 합니다."라는 메시지를 출력해야 한다.
회원가입 성공 시 입력한 회원정보를 DB에 저장해야 한다.

테스트 결과는 다음과 같다.

테스트 내용   실제 결과
비밀번호 7자 입력   회원가입이 정상 처리됨
비밀번호 5자 입력   아무 메시지 없이 회원가입 화면 유지
정상 회원가입   화면에서는 가입 완료가 표시되지만 DB에 저장되지 않음
요구사항

위 세 가지 테스트 결과에 대해 각각 다음 내용을 서술하시오.

결함 여부
결함이라고 판단한 근거
기대 결과와 실제 결과의 차이

CASE 1 : 비밀번호 7자 입력 /  회원가입이 정상 처리됨
결함 여부 : 있음
결함이라고 판단한 근거 : 비밀번호 요구사항은 8자 이상 입력해야 하지만 7자가 정상 통과 되었으므로 결함이 있다.
기대 결과와 실제 결과의 차이 : 기대 결과는 비밀번호가 8자 미만이니 "비밀번호는 8자 이상 입력해야 합니다"라는 메시지와 함께 회원가입이 되지 않아야 하지만, 실제 결과는 회원가입이 정상 처리되었다.
