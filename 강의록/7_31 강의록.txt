연계 오류의 세 가지 유형
 - 연계 시스템 오류 : 인터넷이 끊기거나, 연계 서버/수신 서버 컴퓨터가 꺼진 경우, 방화벽 포트 차단 등 네트워크 및 하드웨어/환경적 장애
 - 연계 프로그램 오류 : 데이터 변환/매핑 프로그램의 버그, 파싱 실패, 연계 어댑터 프로그램 실행 오류 등 소프트웨어 로직 결함
 - 연계 데이터 오류 : PK 중복, 필수 값 누락, 코드 불일치, 데이터 타입 불일치 등 데이터 자체의 정합성/무결성 결함

연계 오류 식별 방법
로그 파일 조회 : 연계 서버, 송수신 어댑터, DB 등의 로그 파일을 확인하여 오류 메시지 및 오류 코드 식별
모니터링 시스템/관제 도구 활용 : 연계 모니터링 화면에서 미처리/실패 건 발생 알림 및 상태 값 확인
I/F 테이블 조회 : 처리 상태 컬럼 조건을 통한 오류 건 검색

연계 오류 원인 분석 방법
오류 코드 및 메시지 해석 : 에러코드와 예외 추적 내역 분석
송/수신 데이터 비교 : 송신 전 데이터와 수신 수 변환/적재된 데이터 간 필드값, 규격, 코드값 차이 검증
통신/네트워크 연결성 점검 : Telnet, Ping, Curl 명령어로 IP/Port 차단 여부 확인

연계 오류 처리 및 재처리 방안
연계 오류 처리 절차
1. 오류 감지/인터셉트 : 시스템 이벤트, 모니터링 열람, 로그 모듈을 통해 에러 발생 즉시 감지
2. 오류 원인 규명 : 
 - 데이터 오류 : 송신 데이터 보정 및 수신 DB 분기 로직(INSERT/UPDATE) 수정
 - 프로그램 오류 : 변환/매핑 로직 수정 및 파서 업데이트
 - 시스템 오류 : 네트워크 포트 오픈 및 재전송/재적재
3. 재처리 수행 : 실패한 건에 대한 재전송/재적재
4. 해결 여부 검증 및 이력관리 : 모니터링 및 DB조회로 최종 성공 확인 후 추적 관리 문서 작성
5. 재처리 실행 방식
 - 자동 재처리 : 네트워크 순간 지연이나 서버 일시 부하 시 연계 엔진이 일정 간격으로 자동 재시도
 - 수동 재처리 : 데이터 수정, 코드 매핑 등록, 방화벽 오픈 등 원인 해결 조치가 완료된 후 관리자 관제 화면에서 [재처리/재시동] 실행
6. 연계 오류 추적 관리 및 예방 관리
 - 오류 추적 관리 및 문서 작성 항목
	ㄴ 인터페이스 ID 및 연계명
	ㄴ 오류 발생 일시 및 오류 코드 / 메시지
	ㄴ 오류 발생 원인 및 대상 데이터 정보
	ㄴ 조치 내용, 조치자, 조치 완료 일시
	ㄴ 재처리 실행 여부 및 최종 처리 결과
 - 동일 문제 재발 방지 예방 관리 방안
	ㄴ 표준 코드 체계 구축 및 중앙 매핑 관리 : 시스템 간 코드 일원화 및 매핑 테이블 관리
	ㄴ 사전 데이터 검증 강화 : 송신 전 필수값, 타입, PK 중복 여부를 체크하는 유효성 검증 로직 추가
	ㄴ 네트워크 / 보안 정책 변경 사전 검토 : 방화벽 변경 전 연계 IP/Port 영향을 검증하는 프로세스 수립
	ㄴ 실시간 관제 알림 체계 강화 : 장애 발생 즉시 담당자에게 알림이 발송되도록 구성

1. 전송 구간 보안 방식 결정
1-1. 전송 구간 암호화 방식을 결정
	- TLS(HTTPS) : Transport Layer Security
		ㄴ 인터넷에서 가장 많이 사용하는 전송 구간 암호화 기술
			ㄴ 웹 서비스 표준 방식
			ㄴ REST API 통신 표준
			ㄴ 브라우저와 서버간 암호화
			ㄴ 가장 많이 사용하는 방식
		장점
		- 구현이 쉽다
		- 대부분의 웹 서비스에서 사용한다
		- 데이터 도청을 방지한다
		단점
		- 서버만 인증한다(단방향성 인증)
		- 서버간 통신에서는 보안이 부족할 수 있다

	- mTLS : mutual TLS
		ㄴ 양방향 인증 방식(나머지는 TLS와 동일)
		장점
		- 보안 수준이 매우 높다
		- 위조 서버 접속 방지
		단점
		- 인증서 관리가 복잡하다

	- SSH(Secure SHell) : 원격 서버 접속 및 파일 전송을 위한 암호화 프로토콜
		장점
		- 안전한 원격 접속
		- 파일 전송 가능
		단점
		- 웹 API에는 사용하지 않는다


암호화 알고리즘
SEED : 1999년 한국인터넷진흥원(KISA)과 국내 암호학자들이 자체 개발한 128비트 대칭키 블록 암호 알고리즘
	- 개발 배경 : 미국 중심의 암호 기술 수입 의존도를 낮추고 국내 전자상거래 및 인터넷 금융의 보안을 강화하기 위해 국산 표준으로 개발되었다.
	- 주요 특징
		ㄴ 블록 크기 : 128비트(16바이트)
		ㄴ 키 길이 : 128비트, 256비트
		ㄴ 구조 : 파이스텔 구조 기반
		ㄴ 규격 : 대한민국 국가 표준
ARIA : 2004년 국가정보원과 산학연 전문가들이 개발한 국가 표준 대칭키 블록 암호화 알고리즘
	- 개발 배경 : 기존 SEED 알고리즘이 경량 환경이나 경량화 기기, SW 경량화 환경에서 효율이 떨어지는 단점을 보완하고 AES 알고리즘과의 경량/경쟁 호환성을 위해 개발되었다
	- 주요 특징
		ㄴ 블록 크기 : 128비트
		ㄴ 키 길이 : 128, 192, 256비트 지원
		ㄴ 구조 : SPN 구조
		ㄴ 장점 : 경량화 환경에 유리하며, 하드웨어 및 소프트웨어 구현 시 비트연산 위주로 동작하여 속도가 빠르고 경량 기기에 적합하다

AES : 
	- 2001년 미국 표준기술연구소가 공모를 통해 지정한 세계적 표준 대칭키 블록 암호 알고리즘이다
	- 개발배경 : DES의 키 길이가 짧아 해킹 위험이 높아짐에 따라 전 세계 표준으로 활용할 강력한 암호화 표준의 필요성으로 탄생했다.
	- 주요 특징
		ㄴ 블록 크기 : 128비트
		ㄴ 키 길이 : 128비트, 192비트, 256비트
		ㄴ 구조 : SPN
		ㄴ 장점 : 안정성, 속도, 메모리 효율성이 뛰어나며 현재 전 세계 대부분의 연계보안에서 가장 널리 쓰이는 사실상의 글로벌 표준이다.


암호화 KEY를 관리하는 방식
1. KEY VAULT(키 볼트)
 - 소프트웨어 기반의 클라우드 암호화 키/비밀정보 관리 서비스
 - 보관 대상 : DB 암호화 키 뿐만 아니라 API 인증키, 비밀번호, SSL/TLS 증명서 등 다양한 비밀정보를 한 곳에서 관리한다
 - 접근 제어 : 어플리케이션이 Key Vault에 접근할 때 정당한 권한이 있는지 확인한 후 키를 제공하거나, Vault 내부에서 직접 암복호화를 수행해준다.

2. HSM(Hardware Security Module)
 - 암호화 키의 생성, 보관, 처리 연산만을 전담하도록 특별히 제작된 '특수 물리 하드웨어 장비'
 - 물리적 보안성 : 장비 내부의 키는 절대 외부로 추출할 수 없도록 설계되어 있다
 - 침입 탐지 및 자멸 기능 : 누군가 장비를 강제로 열거나 물리적인 공격을 시도하면 내부에 저장된 키를 즉시 하드웨어 수준에서 파기한다.
 - 연산 전담 : 암/복호화 연산을 암호화 전용 하드웨어칩이 직접 수행하므로 서버의 CPU 부하를 줄여준다.


암/복호화 알고리즘 방식 파악

1. 대칭키 암호화 : 하나의 암호키로 암호화 복호화를 수행
장점
 - 매우 빠르다
 - 대용량 데이터에 적합

단점
 - 키를 안전하게 전달해야 한다

2. 비대칭키 암호화 : **공개키를 통해 암호화하고 **개인키를 통해 복호화 한다.

** 공개 키(Public Key) : 누구나 볼 수 있도록 공개된 키
 - 데이터를 암호화 하거나, 전자서명을 검증할 때 사용
 - 인터넷이나 연계 시스템을 통해 누구에게나 자유롭게 배포할 수 있다.
 - 공개 키로 암호화된 데이터는 오직 그와 짝을 이루는 개인키로만 복호화 할 수 있다.
 - 공개 키가 외부에 노출되어도 해당 키로는 데이터를 복호화 할 수 없기 때문에 안전하다

** 개인 키(Private Key) : 소유자 본인만 안전하게 보관해야 하는 비밀 키
 - 암호화된 데이터를 복호화 하거나, 전자 서명을 생성할 때 사용한다.
 - 절대로 외부에 유출되어서는 안되며, HSM이나 Key Vault같은 보안 저장소에 안전하게 보관해야 한다.
 - 개인 키를 분실하거나 유출당하면 암호화된 데이터가 해독되거나 타인이 나를 사칭할 수 있게 된다.
