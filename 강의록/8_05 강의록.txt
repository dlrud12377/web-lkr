연계 모듈 테스트 설계
 - 송/수신 시슽메 간 데이터 전송 및 인터페이스 처리 과정에서 발생 가능한 오류, 무결성 위반 등을 검증하기 위해 테스트 케이스를 설계하고, 이를 기반으로 실제 연계 모듈을 시험, 검증하는 활동

필요성
 - 데이터 무결성 보장
 - 업무 연속성 확보
 - 성능 및 확장성 검증
 - 보안성 검증
 - 최신 필요성

<연계 모듈 테스트 설계 절차>

1. 테스트 범위 및 대상
범위 : 송신 시스템 -> 연계 서버 -> 수신 시스템
대상 : DB, 인터페이스 테이블, 로그/오류 테이블, 응용 프로그램

2. 테스트 케이스 설계
 - 송수신 DB 테이블 값 검증, 오류 코드 처리 확인, 전송 후 로그 기록 확인 등을 할 수 있으며, 단위 테스트와 통합 테스트로 구분하여 설계할 수 있다.

3. 테스트 환경 구축
 - 테스트 환경 구축을 위해 Adapter 설치, 연계 서버 구축, 테스트용 db/테이블 생성, 네트워크 보안 설정 등이 필요하다.

4. 테스트 수행
 - 설계된 테스트 케이스에 따라 데이터 전송, 오류 유발, 복구 절차 등을 실행한다
정상 시나리오, 비정상 시나리오로 구분하여 실시할 수 있다.

5. 테스트 결과 검증 및 기록
 - 데이터 건수 일치 여부, 변환된 코드값 확인, 로그 모니터링 값 검증 등을 하며 결과비교를 위해 SQL 쿼리, 로그 파일, 모니터링 대시보드를 활용한다.

6. 리뷰 및 개선
 - 오류 발생 시 원인 분석 및 수정, 재시험을 수행하며, 자동화된 회귀 테스트 체계로 재시험을 수행한다.

<연계 모듈 테스트 설계 시 유의 사항>

1. 데이터 정확성
 - 송/수신 DB간 값, 건수, 포맷 일치를 확인한다

2. 에러 처리
 - 예상치 못한 오류 발생 시 로그 기록, 오류 코드 변환, 관리자 알림 체계가 필요하다.

3. 보안성
 - 테스트 데이터도 개인정보, 민감정보 포함 간으 시 마스킹, 익명화 처리가 필요하다

4. 성능 검증
 - 실시간 연계 대응 및 대용량 배치 환경 각각 테스트를 수행한다

5. 운영 환경 유사성 확보
 - 테스트 환경이 최대한 동일해야 한다

6. 자동화 지원
CI/CD 파이프라인과 연계하여 자동 테스트 실행, 결과 대시보드 제공을 할 필요가 있다.

<최신 동향>

1. 테스트 자동화
 - Selenium, JUnit, Postman, Apache JMeter, K6 등의 자동화 도구를 활용하고 API Gateway 환경에서 Open API 기반 자동 생성 테스트 스크립트를 활용한다.

2. 데이터 검증 고도화
 - 단순 SQL 비교에서 데이터 품질 검증 도구와 연계하여 데이터 검증을 고도화한다.

3. 클라우드 MSA 환경 대응
 - Kubernetes 환경에서 Service Mesh 기반 모니터링 및 트래픽을 제어하며, 마이크로서비스 간 API 연계 테스트를 통해 Contract Testing이 확산되고 있다.

4. 실시간 로그/모니터링
 - ELK Stack, Prometheus + Grafana를 활용하며, 오류 발생 시 AI 기반 Root Cause Analysis를 적용한다.

5. AI/ML 활용
 - 테스트 케이스 자동 생성 및 우선순위를 추천하며, 로그/모니터링 데이터를 기반으로 한 예측적 장애 감지를 한다.

<연계 모듈 테스트 설계하기>
1. 연계 모듈 테스트 구간 및 범위 파악하기

2. 연계 모듈 테스트 케이스를 작성하고 명세화 한다.
 - 송/수신용 연계 응용 프로그램 단위 테스트 케이스를 작성하고 명세화 한다.
	ㄴ 테스트 환경은 운영 환경과 동일하거나 유사하게 작성한다.
	ㄴ 테스트 케이스는 송/수신 시스템에서 확인해야 할 사항을 각각 도출하며, 단순 개별 데이터의 유효값을 체크하는 경우의 수와 데이터 간의 연관 관계를 체크하는 경우의 수로 식별하여 작성한다.
	ㄴ 단순 개별 데이터 유효값은 코드일 경우, 코드 테이블에 등록된 값의 여부 똔느 유효 데이터 타입, 길이, 필수 입력 여부 등의 체크를 의미한다.
	ㄴ 데이터 간의 상관관계 체크는 특히, 수신 시스템에서 운영 DB에 반영하는 연계 응용 프로그램에서 등록되어 있지 않은 데이터에 대해서 수정이나 변경이 발생하였거나 또는 참조하는 테이블에 데이터가 없는 경우에 데이터를 등록하는 경우의 점검이 해당된다.
 - 연계 테스트 케이스를 작성하고 명세화 한다.

3. 연계 테스트를 수행 및 검증한다.
 - 연계 테스트 환경 구축
	ㄴ 운영 환경과 비슷하게 구축한다.
	ㄴ 연계 서버, 송수신용 어댑터 또는 에이전트 설치를 비롯하여 송수신 운영 DB에서 연계 데이터 추출 및 반영에 필요한 테이블, 데이터와 송수신용 연계 응용 프로그램들을 설치 및 준비한다.
	ㄴ 송수신 기관 간에 테스트 수행 전에 연계 테스트 일정, 절차, 방법, 소요 시간, 테스트 환경, 환경 구축 기간 등을 협의하여 계획을 수립하고, 환경을 구축한다.

 - 연계 테스트를 수행한다
	ㄴ 연계 테스트 케이스의 시험 항목 및 처리 절차대로 실제 연계 응용 프로그램을 실행하며 테스트하고 결과를 확인한다

 - 연계 테스트 수행 결과를 검증한다
	ㄴ 연계 테스트 케이스의 시험 항목 및 처리 절차 순서에 따라 테스트를 진행하면서 수행한 테스트 결과가 예상한 정상적인 결과인지를 확인하기 위해 검증을 수행한다.
	ㄴ 테스트 결과는 테스트 하는 항목에 따라 다르게 검증한다
	ㄴ 통합 테스트에서는 송신 시스템에서 데이터를 생성하는 응용 어플리케이션의 기능을 이용하여 데이터를 생성하고, 수신 시스템의 운영 응용 어플리케이션 화면에서 송신 시스템에서 송신한 데이터가 유효한 값으로 검색이 된다면 정상적으로 데이터가 송수신되어 처리된 것으로 확인할 수 있다.
	( 데이터 생성(BY 송신 응용 APP) -> 수신 APP DISPLAY에서 유효값 검색됨 : 데이터 정상 송수신 처리 )

4. 연계 테스트 케이스를 작성 및 명세화 한다.

 - 송/수신용 연계 응용 프로그램에 대한 단위 테스트 케이스를 각각 작성하고 명세화 한다.
	ㄴ 단위 테스트 케이스는 프로그램 단위의 기능상 결함을 확인할 수 있는 항목으로 도출하여, 연계 단위로 작성한다. 발생 가능한 오류에 대해서도 처리하고 있는지 확인할 수 있는 테스트 케이스 항목을 식별하여 명세화 한다.
	ㄴ 테스트 케이스는 정상적인 기능 수행 외에도 처리 과정상 각 연계 데이터 항목이 가질 수 있는 데이터값의 유효 범위를 참고하여 오류 발생에 대한 처리 사항 체크 여부도 포함하여 작성한다

 - 연계 테스트 케이스를 작성하고 명세화 한다
	ㄴ 수신 시스템에서 데이터 추출,
	송신용 연계 테이블 및 데이터 생성,
	송수신,
	수신용 연계 테이블 및 데이터 생성,
	송신 시스템 운영 DB의 테이블에 데이터 반영
	까지가 중단 없이 수행되는지를 확인할 수 있도록 테스트 케이스 항목을 식별하여 작성한다.

5. 연계 테스트 환경을 구축한다.
 - 송수신 기관 간의 사전 협의를 통해 테스트 기간, 방법, 절차, 환경, 환경 구축 기간 등을 결정하고 연계 테스트 환경을 구축한다.
	ㄴ 테스트 환경 및 테스트 수행을 위해 송수신 기관 간의 협의 시 일정 수립 및 준비 사항에 연계 테스트를 위한 테스트 환경 구축 점검 및 준비사항을 참고한다.
	ㄴ 송수신 기관 간의 협의된 결과에 따라, 연계 서버 및 송수신 어댑터 및 에이전트 설치, 연계를 위한 아이피 및 포트 허용 신청, 연계를 위한 DB계정 및 테이블과 데이터 생성 등 테스트 환경 구축
 
 - 연계 테스트 환경 점검
	ㄴ 송/수신 데이터베이스 사용자 생성 여부를 점검
	ㄴ 송신 데이터베이스의 채용 공고 테이블, 사용자 테이블, 코드 테이블, 오류 코드 테이블, 코드 매핑 테이블 생성 및 각 테이블 데이터 입력 여부를 점검한다.
	ㄴ 수신 데이터베이스의 공고 정보 테이블, 코드 테이블, 오류 코드 테이블 생성 및 각 테이블 데이터 입력 여부를 점검
	ㄴ 디렉터리 생성 및 권한 부여 여부를 점검
	ㄴ신 디렉터리 생성 및 권한 부여 여부를 점검

6. 테스트 수행 및 테스트 수행 결과를 검증
 - 송신 시스템의 연계 응용 프로그램을 실행하여 단위 테스트를 수행하고 결과를 검증한다
	ㄴ 테스트 케이스 항목의 순서대로 테스트
	ㄴ 테스트 결과는 테스트 케이스의 항목별 검증 방법으로 검증한다.
 - 생성된 송신 시스템 연계 파일을 수신 디렉터리의 연계 파일 위치에 복사하여 이동시키고, 연계 파일명을 수신용 연계 파일명의 기준에 맞도록 수정한다.
 - 수신 시스템의 연계 응용 프로그램을 실행하여 단위 테스트를 수행하고 결과를 검증한다.
	ㄴ 테스트 케이스 항목의 순서대로 테스트한다.
	ㄴ 테스트 결과는 테스트 케이스의 테스트 케이스 항목별 검증 방법으로 검증한다.
