Index - create(ddl)
 - 조회를 빠르게 하기 위한 목적으로 사용
 - where, order by, group by에 많이 사용되는 속성에 대해 미리 접근 위치를 기록해놓는다.(중간 세이브포인트 느낌)
 - 실제 조회를 할 때 해당 컬럼이 사용되면 index가 자동으로 사용
 - insert, update, delete와 같이 테이블 수정에 있어서는 불리하다.

 - 인덱스 생성문
CREATE INDEX 인덱스명
ON 테이블(칼럼)

 - 테이블에 어떤 인덱스가 존재하는지 확인
SHOW INDEX FROM 테이블명;

 - 인덱스 삭제
DROP INDEX 인덱스명 ON 테이블명;


Sub Query - dml
 - SQL문 안에 SQL문이 있는 형태
 - 특정 조건을 다른 테이블 조회 결과로 판단할 때
 - 평균값, 최대값 같은 계산 결과를 기준으로 조회할 때
 - JOIN 없이 단계적으로 데이터를 조회하고 싶을 때 사용

 - 종류
	- 단일 행 서브쿼리 : 결과가 1개
	- 다중 행 서브쿼리 : 결과가 여러개
	- 다중 컬럼 서브쿼리 : 컬럼이 여러개
	- 상관 서브쿼리 : 바깥 쿼리와 연결됨
	- FROM절 서브쿼리 : 가상 테이블처럼 사용함 -> VIEW로 대체 가능

 - 사용기호
	- IN(중 하나), ANY(해당 조건 중 하나라도), ALL(해당 조건 전부)


Join - dml
 - 정규화를 통해서 분리된 테이블을 공통된 컬럼을 기준으로 연결해서 조회하는 기능

INNER JOIN
 - 두 테이블에서 조건이 일치하는 데이터만 조회

LEFT OUTER JOIN
 - 왼쪽 테이블(FROM 절에 작성된 테이블)의 데이터는 전부 조회하고, 오른쪽 테이블(JOIN된 테이블)의 데이터는 조건이 맞는 데이터만 조회
 - 없는 데이터 쪽은 NULL로 표시

RIGHT OUTER JOIN
 - LEFT OUTER JOIN과 동일하나, 오른쪽 테이블 전부 / 왼쪽 테이블 조건이 맞는 데이터만 조회
 - 방향만 바뀐거라 잘 사용하지는 않음(필요하다면 테이블 순서를 바꿔서 LEFT를 사용)

CROSS JOIN

JOIN 테이블 별칭
ON 외래키 연결관계

JOIN의 무결성
 - 외래키가 없어도 조인은 가능하나, 무결성을 해칠 수 있기 때문에 권장하지 않는다.

** 무결성의 주요 종류 (데이터베이스 기준)
개체 무결성 (Entity Integrity): 기본 키(Primary Key)는 고유한 값을 가져야 하며 Null(빈 값)일 수 없습니다.
참조 무결성 (Referential Integrity): 관계형 데이터베이스에서 두 테이블의 데이터는 일관되게 참조 관계를 유지해야 합니다.
도메인 무결성 (Domain Integrity): 특정 필드에 입력되는 값이 정의된 데이터 형식, 범위, 규칙을 따르는 것을 의미합니다.
사용자 정의 무결성 (User-defined Integrity): 비즈니스 규칙에 따라 사용자가 정의한 특정 제약 조건을 따릅니다

컬럼명의 충돌
 - 두 테이블에 같은 이름의 컬럼이 있으면 어느 테이블에서 조회하려는 것인지 명확하게 작성을 한다.
EMPLOYEE.EMP_ID, ENROLL.EMP_ID

-- 고객이름, 주문한 제품명을 left outer join을 이용하여 조회하기
select c.customer_name, p.product_name
from orders o
left outer join product p
on p.product_id = o.product_id and product_name = '노트북' -- 노트북 이외에는 left outer join이므로 다 null표시
left outer join customer c
on c.customer_id = o.customer_id;
-- on이 where의 역할처럼 조건을 봐주기 때문에 테이블 생성 단계에서 조건을 걸려면 on에 걸어주는 것이 맞음
-- where은 테이블이 다 join되고 나서 진행이 됨 -> left outer join을 하더라도 조건에 안맞으면 표시되지 않음


View - create(ddl)
 - 조회된 결과(SELECT문의 결과)를 저장할 수 있는 가상의 테이블

복잡한 SELECT문을 간단하게 저장할 수 있는 효과가 있음
VIEW를 만든다고 해서 실제로 데이터가 저장되는 것은 아님
원본데이터가 바뀌면 VIEW에 들어있는 데이터도 바뀐다.(얕은복사?)

VIEW안에서 VIEW를 사용하는 것이 가능하기는 하나 성능저하가 일어날 수 있다.

AUTO_INCREMENT
 - 숫자 값을 자동으로 1씩 증가시켜서 입력해주는 속성
 - 데이터를 추가할 때마다 직접 번호를 입력하면 번거롭기 때문에 사용함
 - 반드시 숫자 타입의 컬럼에만 붙여야한다.
 - 인덱스가 있어야 하기 때문에 PK와 함께 사용함
 - 한 테이블에 하나만 사용할 수 있음
 - 직접 값을 넣을 수도 있음
INSERT INTO board(board_id, title, content)
values (100, '관리자 공지', '직접 번호 입력');
그 다음 자동 증가 값은 보통 101부터 시작한다.
 - 중간 번호는 재사용하지 않는다.
1	첫번째글
2	두번째글
3	세번째글

delete from board where board_id = 3
다음과 같이 3번째 글을 삭제하면 새로운 insert값은 4부터 진행
1	첫번째글
2	두번째글
4	네번째글

 - AUTO_INCREMENT는 연속 번호 보장용이 아니라 고유 식별자 생성용임

 - INSERT 했다가 ROLLBACK을 해도 다음 번호로 건너뜀
 - 테이블 생성 후 다음 자동 증가값을 바꿀 수 있음
ALTER TABLE 테이블명 AUTO_INCREMENT = 1000;
이후 새 데이터는 1000부터 들어갈 수 있다.

 - 현재 AUTO_INCREMENT 값 확인하기
SHOW TABLE status LIKE '테이블명';

LIMIT
 - 조회 결과를 제한하는 절
 - 원하는 만큼만 보여줌

SELECT *
FROM 테이블
LIMIT 5;

ORDER BY와 함께 많이 사용된다.
내림차순으로 정렬해서 상위 5개만 조회

데이터가 몇백만건 들어있는 테이블에서 LIMIT이 없으면 위험할 수 있음
 -> 페이징 처리할 때 사용
SELECT *
FROM BOARD
ORDER BY BOARD_ID DESC
LIMIT 5;

SELECT *
FROM BOARD
ORDER BY BOARD_ID DESC
LIMIT 10, 10, 10;

Stored Program
 - 절차형 SQL 문법
 - MySQL 안에서 프로그래밍처럼 SQL을 실행하기 위한 문법
 - Stored Procedure : MySQL 서버 안에 저장해두고 실행하는 프로그램의 단위
 - Stored Function : 값을 계산해서 변환하는 함수
 - Trigger INSERT, UPDATE, DELETE시 자동 실행
 - Event : 정해진 시간마다 자동 실행

일반 SQL문은 한문장씩 실행이 된다.
Sorted Program에서는 SQL에 프로그래밍적인 요소를 집어넣을 수 있다.
변수
조건문
반복문
예외처리

상품 주문 로직
1. 상품 재고 조회 -> select
2. 재고가 충분한지 조회 -> select
3. 재고 차감 -> update
4. 주문 데이터 저장 -> insert
5. 결과 반환

Stored Program의 핵심 구조
DELIMITER //
CREATE PROCEDURE hello()
BEGIN
	SELECT 'Hello MySQL Stored Program' AS message;
	set~

DELIMITER;

* DELIMITER
MySQL에서 기본적으로 세미콜론을 만나면 SQL 문장이 끝났다고 판단함
프로시저 전체가 끝날 때까지 ;로 끝난 것으로 보지 말고, // 만났을 때 끝난 것으로 판단해라

* BEGIN ~ END는 여러 SQL문장을 하나의 블록으로 묶는 방법(자바 중괄호와 같은 방식)
BEGIN
	문장1;
	문장2;
	문장3;
END

* DECLARE : 변수 선언
DECLARE 변수명 자료형 DEFAULT 기본값;

DECLARE v_count int default 0
DECLARE v_name varchar(50) default '홍길동'

BEGIN ~ END 블록의 가장 앞부분에 작성해야 한다.
일반 SQL문 뒤에 선언하면 오류가 난다.

BEGIN
DECLARE v_num int default 0;
SET v_num = 100;
select '시작';

END;

* SET : 변수에 값을 넣음
set 변수명 = 값;


* 매개변수 IN, OUT, INOUT
 - IN은 외부에서 값을 받아오는 매개변수
 - CREATE PROCEDURE 프로시저명(IN 매개변수명 타입)

IN은 외부에서 값을 받아오는 매개변수
CREATE PROCEDURE 프로시저명(IN 매개변수명 타입)

OUT은 프로시저 내부에서 만든 값을 외부로 내보내는 매개변수
CREATE PROCEDURE 프로시저명(OUT 매개변수명 타입)
