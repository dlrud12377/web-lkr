 - 개선 사례 : 성공/실패에 적절한 무늬를 다르게 넣고, 글씨를 넣어 구분을 확실하게 한다.

 - 접근성 : 장애인, 고령자, 신체적 제약이 있는 사람을 포함한 모든 사용자가 어떤 환경에서든 차별없이 시스템을 이용할 수 있도록 보장하는 정도

 - 개선 사례 : 색상이라는 하나의 시각 단서에만 의존하지 않고, 텍스트 메시지나 명확한 아이콘을 함께 결합하여 색을 보지 않고도 정보를 명확히 인지할 수 있도록 설계해야 한다.


[Q10] 스마트폰이나 태블릿 같은 모바일 플랫폼과 PC 환경인 데스크톱 플랫폼은 조작 방식과 화면 특성이 다릅니다. 가이드라인에 명시된 두 플랫폼의 핵심 차이점과 그에 따른 UI 설계 시 고려사항을 비교하여 서술하시오.
 - 
모바일 플랫폼
 - 화면 크기가 제한적이다.
 - 손가락 터치 및 제스처로 조작한다.
 → 이로 인해 버튼이 너무 작으면 사용하기 힘들다.
 → 따라서 버튼 크기를 크게 설계해야 하고 정보 밀도를 낮춰(한 화면에 적은 정보) 한번에 하나의 작업에 집중할 수 있도록 단일 열 배치가 선호된다.

데스크톱 플랫폼
 - 키보드와 마우스 중심으로 정밀하고 세밀하게 조작한다.
 - 화면이 크기 때문에 많은 정보를 한 번에 보여줄 수 있다.
 → 따라서 한 화면에 많은 양의 정보를 효율적으로 배치할 수 있으며, 마우스 전용 상호작용을 적극 활용할 수 있다.

[Q11] UI(User Interface)와 UX(User Experience)는 밀접하지만 서로 다른 개념입니다. 본문에 제시된 자동차 비유를 활용하여 두 개념의 차이점을 상세히 설명하시오.

 - UI는 사용자가 사용할 수 있는 조작 환경, 즉 자동차에서는 계기판, 핸들, 버튼, 네비게이션 화면 등등을 의미한다.
	→ 물리적, 시각적 요소를 의미

 - UX는 사용자가 느끼는 경험을 의미하며, 자동차에서는 매력도(승차감, 만족감), 직관성, 기능 사용의 용이함(운전의 편리함, 피로도) 등을 의미한다. 
	→ 총체적인 경험과 지각을 의미

 → 디자인(UI)이 아무리 화려하더라도 불편하면 경험(UX)이 좋지 않을 수 있다.

 - 요구사항 파악 → 설계/디자인 → 프로토타입 제작 → 사용자 테스트/평가 → (문제 발견 → 수정 → 재테스트) → 완성

[Q13] 인터랙션 설계 품질을 높이기 위한 '좋은 상호작용(Interaction)'의 세 가지 분석 항목(직관성, 효율성, 피드백 제공)에 대해 각각의 개념이나 예시를 들어 설명하시오

 - 
직관성 : 사용 시 내용이 명확해야 한다. 예를 들어 회원가입 버튼에 '완료'라고 적지 않고, '회원가입 완료'라고 명시를 해 주어야 한다.
효율성 : 조작이 단순해야 한다. 예를 들어 메인 페이지에서 어떤 페이지든 클릭 5번 안에 갈 수 있어야 한다.
피드백 제공 : 어떤 행위에 대한 결과 피드백을 명확하게 제공해야 한다. 예를 들어 저장 버튼을 클릭하면 저장이 완료되었다는 메시지가 떠야 한다.

직관성 : 사용자가 별도의 메뉴얼이나 가이드 없이도 UI의 형태만 보고 기능을 곧바로 조작하고 이해할 수 있는 성질( 돋보기 아이콘 -> 검색, 집 아이콘 -> 홈 화면)

효율성 : 사용자가 원하는 목표나 태스크를 달성하기까지 거치는 단계를 최소화하여 시간과 노력을 줄여주는 성질

피드백 제공 : 사용자가 시스템에 특정 행동을 했을 때, 시스템이 그 결과를 즉각적이고 명확하게 인지시켜 주는 것
(저장버튼 눌렀을 때 "성공적으로 저장되었습니다" 메시지 띄우기)


[Q14] 사용자 조사 및 면담 과정에서 질문자가 범하기 쉬운 오류를 방지하기 위해 '중립성'을 유지해야 합니다. 본문에 제시된 잘못된 질문 예시와 올바른 질문 예시를 비교하여 중립성 유지가 왜 중요한지 설명하시오.

 - 잘못된 질문 : 현재 메뉴가 복잡하지 않습니까?
 -> 현재 메뉴가 복잡하다는 대답을 본의 아니게 유도할 수 있음. 질문자 본인의 주관적 판단을 섞었기 때문
 - 올바른 질문 : 현재 메뉴 구조에 대해 어떻게 생각하십니까?
 -> 현재 메뉴에 대해 자유롭게 가지고 있는 생각을 이야기할 수 있음. 선입견 없이 사용자의 순수한 의견을 이끌어냄

-> 중립성을 유지하지 않으면 설문 데이터가 방향성을 가지고 오염될 수 있다.
 (질문자가 유도성 질문을 던지면 사용자는 솔직한 의견 대신 질문자의 의도에 맞춘 왜곡된 답변을 하게 된다. 이는 잘못된 요구사항 수집으로 이어져 결국 사용자 중심 설계에 실패하는 원인이 되기 때문에 객관적인 중립성 유지가 매우 중요하다.)
