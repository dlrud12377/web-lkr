[Q3] 소프트웨어 요구사항을 문서로 정리할 때 참고하는 표준으로, UI 요구사항 명세를 명확한 문장으로 작성하여 개발자, 디자이너, 기획자가 같은 의미로 이해할 수 있도록 돕는 국제 표준 규격의 이름은 무엇인가?

[Q9] '접근성(Accessibility)'의 개념을 정의하고, 본문에서 지적한 '색상만으로 성공/실패를 구분하는 잘못된 사례'가 색약 사용자에게 미치는 문제점과 이를 해결하기 위한 '개선 사례'의 핵심 원리를 서술하시오.
 - 접근성은 모든 사용자가 소프트웨어를 사용할 수 있는지를 나타내는 UX의 구성 요소이다.
 - 색약 사용자에게 미치는 문제점 : 색약은 색을 통해 성공/실패를 구분할 수 없어 접근성이 떨어진다.
 - 개선 사례 : 성공/실패에 적절한 무늬를 다르게 넣고, 글씨를 넣어 구분을 확실하게 한다.


[Q10] 스마트폰이나 태블릿 같은 모바일 플랫폼과 PC 환경인 데스크톱 플랫폼은 조작 방식과 화면 특성이 다릅니다. 가이드라인에 명시된 두 플랫폼의 핵심 차이점과 그에 따른 UI 설계 시 고려사항을 비교하여 서술하시오.
 - 
모바일 플랫폼 : 손가락을 이용하여 터치하며, 이로 인해 버튼이 너무 작으면 사용하기 힘들다.
데스크톱 플랫폼 : 키보드와 마우스 중심으로 조작하며, 화면이 크기 때문에 많은 정보를 한 번에 보여줄 수 있다.
-> 이로 인해 모바일 환경에서는 한 화면에 많은 정보를 담지 않고, 버튼을 크게 만들어 조작하기 편하게 해야 한다.
반대로 데스크톱의 경우는 화면에 필요한 정보를 한 눈에 볼 수 있도록 많이 담고, 버튼은 모바일에 비해 작게 만들어도 괜찮다.

[Q11] UI(User Interface)와 UX(User Experience)는 밀접하지만 서로 다른 개념입니다. 본문에 제시된 자동차 비유를 활용하여 두 개념의 차이점을 상세히 설명하시오.

 - UI는 사용자가 사용할 수 있는 조작 환경, 즉 자동차에서는 계기판, 핸들, 버튼, 네비게이션 화면 등등을 의미한다.
 - UX는 사용자가 느끼는 경험을 의미하며, 자동차에서는 운전의 편리함, 기능 사용의 용이함, 매력도 등을 의미한다. 

[Q12] 국제 표준 ISO 9241-210에서 강조하는 핵심 원칙 중 하나는 "설계는 반복적으로 이루어져야 한다"입니다. 본문에서 예시로 든 '회원가입 버튼' 사례를 포함하여, 이 반복적 설계 과정이 어떤 순서 순환 구조로 진행되는지 기술하시오.

 - 설계 -> 프로토타입 제작 -> 사용자 테스트 -> (문제 발견 -> 수정 -> 재테스트) -> 완성

[Q13] 인터랙션 설계 품질을 높이기 위한 '좋은 상호작용(Interaction)'의 세 가지 분석 항목(직관성, 효율성, 피드백 제공)에 대해 각각의 개념이나 예시를 들어 설명하시오

 - 
직관성 : 사용 시 내용이 명확해야 한다. 예를 들어 회원가입 버튼에 '완료'라고 적지 않고, '회원가입 완료'라고 명시를 해 주어야 한다.
효율성 : 조작이 단순해야 한다. 예를 들어 메인 페이지에서 어떤 페이지든 클릭 5번 안에 갈 수 있어야 한다.
피드백 제공 : 어떤 행위에 대한 결과 피드백을 명확하게 제공해야 한다. 예를 들어 저장 버튼을 클릭하면 저장이 완료되었다는 메시지가 떠야 한다.

[Q14] 사용자 조사 및 면담 과정에서 질문자가 범하기 쉬운 오류를 방지하기 위해 '중립성'을 유지해야 합니다. 본문에 제시된 잘못된 질문 예시와 올바른 질문 예시를 비교하여 중립성 유지가 왜 중요한지 설명하시오.

 - 잘못된 질문 : 현재 메뉴가 복잡하지 않습니까?
 -> 현재 메뉴가 복잡하다는 대답을 본의 아니게 유도할 수 있음.
 - 올바른 질문 : 현재 메뉴 구조에 대해 어떻게 생각하십니까?
 -> 현재 메뉴에 대해 자유롭게 가지고 있는 생각을 이야기할 수 있음

-> 중립성을 유지하지 않으면 설문 데이터가 방향성을 가지고 오염될 수 있다.

문제: 화면 설계 과정 없이 요구사항 분석 후 바로 시스템 개발(코딩)에 착수했을 때, 프로젝트 후반부에 발생할 수 있는 수정 비용 및 시간적 측면의 부작용을 초기 프로토타입 목적과 연결하여 서술하시오.

 - 요구사항 분석 후 바로 개발에 착수하게 되면, 나중에 프로그램이 완성이 되었을 때 사용자가 원하는 방향성과 맞지 않는다면 처음부터 다시 만들어야 한다. 따라서 초기 프로토타입을 통해 실제 화면 설계 전에 사용자의 반응을 빠르게 확인하여 요구에 어긋나서 필요한 비용과 시간을 절약할 수 있다.

문제: UI 구성 요소를 설계할 때, '저장' 버튼과 '취소' 버튼의 화면 내 배치 및 간격 규칙을 일관성(Consistency) 측면에서 어떻게 적용해야 하는지 그 설계 원칙을 서술하시오.

 - 저장 버튼과 취소 버튼은 사용자가 자주 누르게 될 버튼이므로, 어떤 화면에서든간에 크기 및 방향성이 일치하여 프로그램 사용 시 혼란이 없도록 만들어야 한다.

문제: 본문 교재에서는 나쁜 오류 메시지의 예시로 'Error 500'을 제시했습니다. 사용성 측면에서 이를 지양해야 하는 이유를 좋은 오류 메시지가 갖춰야 할 3가지 요소(문제 상황, 해결 행동, 표현 방식)와 비교하여 서술하시오.

 - 해당 오류 메시지는 사용자가 메시지를 확인했을 때 쉽게 오류 상황과 해결을 위한 방향성을 알지 못한다. 따라서 오류 메시지는 어떤 문제가 발생했는지(문제 상황), 이를 어떻게 해결해야 하는지(해결 행동), 이를 어떻게 보여주는지(표현 방식) 3가지 요소를 내포하고 있어야 한다.
