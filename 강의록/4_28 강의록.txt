 < 복습 >
 
	< 데이터 모델링 >
		- 현실 세계의 업무 내용을 데이터베이스에 저장할 수 있도록 데이터 구조로 설계하는 과정

	< 모델링 필요한 이유 >
		- 이상현상의 발생을 막아야 한다.
			1. 데이터 중복이 발생할 수 있다.
			2. 갱신 이상 -> 같은 정보가 여러개 저장되어 있을 때 전부 수정하지 않아서 데이터의 불일치가 일어나는 현상
			3. 삭제 이상 -> 필요 없는 데이터를 지우려다 필요한 데이터까지 삭제하는 경우
			4. 삽입 이상 -> 필요한 데이터를 추가하려다 필요없는 데이터까지 추가하는 경우

	< 데이터 모델링 과정 >
		1. 요구사항 분석
			- 업무에서 어떤 데이터를 관리해야 하는지 파악하는 단계
			- 주요 명사를 찾아 엔티티(Entity, 존재)로 만든다.

		2. 개념적 모델링
			- 업무 내용을 큰 그림으로 표현하는 단계이다.
			- 주로 ERD(Entity Relationship Diagram)를 사용한다.

		3. 주요 구성 요소
			- 엔티티(Entity) : 관리해야 할 대상
			- 속성(Attribute) : 엔티티가 가진 정보
			- 관계(Relationship) : 엔티티 간 연결
			- 식별자(Identifier) : 데이터를 구분하는 값

		4. 논리 모델링
			- 개념적 모델을 실제 테이블 구조에 가깝게 바꾸는 단계
			- ERD를 가지고 테이블을 설계
				< 엔티티 간 관계 설정 >
				(1). 관계를 문장으로 처리
					ex. 학생은 수강신청을 한다.
					수업은 수강신청을 받는다.
					강사는 수업을 담당한다.

				(2). 관계 차수 정하기
					- 1:1, 1:N, M:N 중 어떤 관계인지 정한다.
					ex.
 					학생 1명은 여러 수강신청을 할 수 있다. -> 학생 1 : 수강신청 N
					수업 1개는 여러 수강신청을 받을 수 있다. -> 수업 1 : 수강신청 M
					강사 1명은 여러 수업을 담당할 수 있다. -> 강사 1 : 수업 K

					학생 N : 수업 M이므로 이를 수강신청이라는 중간 엔티티를 이용해 1:N과 1:M으로 풀어준다.(제 1 정규화)
					-> 학생 1 : N - 수강신청 - M : 1 수업

			- 테이블의 이름이나 속성의 이름을 정하는 단계
			- 제약조건(PK, FK 등...) 정규화

		5. 정규화
			- 실무에서는 보통 3차까지 다룸 -> 더 하면 오히려 조회속도가 느려짐
			(1). 1NF(제1정규화) : 속성 하나에는 하나의 값만 들어가야 한다.

			ex
			학생번호		이름		휴대폰 번호
			1			김민수	010-1111, 010-2222 -> 분리
			2			이영희	010-3333

->			학생번호		이름		휴대폰 번호
			1			김민수	010-1111
			1			김민수	010-2222
			2			이영희	010-3333


			(2). 2NF(제2정규화) : 복합 키 중에 일부 컬럼에만 의존하는 컬럼이 있으면 분리(부분 함수 종속 제거)

			ex
			학생번호		과목번호	이름		나이		과목		성적
			1			101		김민수	19		Java		A
			2			202		이영희	19		Python	B
			과목번호 -> 과목
			학생번호 -> 이름/나이
			과목번호 + 학생번호 -> 성적
			이런 종속 관계가 있으므로 3개의 테이블로 분리
			
->			학생번호		이름		나이
			1			김민수	19
			2			이영희	19

			학생번호		과목번호	성적
			1			101		A
			2			202		B

			과목번호		과목
			101			Java
			202			Python

			(3). 3NF(제3정규화) : 일반 컬럼이 다른 일반 칼럼을 결정하면 안된다. (이행 함수 종속 제거)
			** 이행 함수 종속 : X->Y이고 Y->Z일때 X->Z가 성립하면 이행 함수 종속

			ex
			학생번호	이름		전공번호	전공이름
			1		김민수	10	컴공
			2		이영희	20	디자인

			중간에 다른 컬럼을 거쳐서 결정되면 분리

->			학생
			학생번호	이름		전공번호
			1		김민수	10

			전공
			전공번호	전공이름
			10		컴공


			** BCNF(Boyce-Codd Normal Form)
			- 제 3정규형을 좀 더 엄격하게 적용한 정규형
			- 모든 함수적 종속에서 결정자는 반드시 후보키여야 한다.
				** 결정자 : 관계형 데이터베이스에서 다른 속성의 값을 유일하게 결정짓는 속성들의 집합(A -> B)
				** 후보키 : PK가 될 수 있는 속성

			제 3정규형을 지켜도 이상 현상이 남아있을 수도 있기 때문에, 이 과정을 진행한다.

			ex.
			학생명		과목		강사
			김민수		DB		이강사
			김민수		OS		박강사
			이영희		DB		이강사
			
			과목이 결정자인데 후보키가 아님(과목에 따라 강사가 결정되는데 PK는 학생명)

->			과목
			과목명		강사
			DB			이강사
			OS			박강사

			학생
			학생명		과목
			김민수		DB
			김민수		OS
			이영희		DB

			(4). 4NF(제4정규화) -> 다중값 종속 제거
			한 엔티티가 서로 독립적인 여러 값 집합을 가지면 분리

			ex
			학생명	기술		취미
			김민수	JAVA		축구
			김민수	JAVA		게임
			김민수	PYTHON	게임
			김민수	PYTHON	게임

->			학생 기술
			학생명	기술
			김민수	JAVA
			김민수	PYTHON

			학생 취미
			학생명	취미
			김민수	축구
			김민수	게임

			(5). 5NF(제5정규화) : 조인 으로 복원 가능한 경우 분리
			- 어떤 테이블이 여러 개의 테이블로 분해되었을 때 JOIN을 하면 항상 원래 테이블이 나올 수 있는지 확인
			- 원래 테이블이 나온다면 분리하기

			ex
			학생명	과목		강사
			김민수	DB		이강사
			김철수	OS		박강사


->			학생
			학생명	과목
			김민수	DB
			김철수	OS

			강사
			과목		강사
			DB		이강사
			OS		박강사

			담당선생님
			학생명	강사
			김민수	이강사
			김철수	박강사


	6. 물리 모델링
		- 논리적 모델을 실제 DBMS에서 실행 가능한 SQL로 바꾸는 것
		1. 컬럼 타입 구체적으로 정하기
		2. NULL 허용 여부 정하기
		3. 중복 불가 조건 정하기
		4. 기본값 정하기(DEFAULT)
		5. 외래키 제약조건 정하기


 < DML(Data Manipulation Language > : 데이터 조작어

 - 데이터에 대해서 조회, 수정, 추가, 삭제하는 명령어

SELECT (칼럼명1, 칼럼명2, ...) FROM 테이블;

모든 내용을 조회하고 싶을 때
SELECT * FROM 테이블;

특정 조건에 맞는 데이터만 조회하고 싶을 때
- WHERE 조건
- WHERE절은 FROM절 뒤에 작성을 한다.
	- 조건
		1. db에서 = : 같다 / != or <> : 같지않다
		2. 여러 개의 조건을 걸 때
			AND : 그리고
			OR : 또는

		3. NULL값이 들어있는 데이터를 조회
		IS NULL

		4. NULL값이 없는 데이터를 조회
		IS NOT NULL

		5. 날짜 비교
		hire_date >= '1990-01-01'; (1990년 1월 1일 이후 데이터 조회시)
		
		* BETWEEN : 두 날짜 또는 숫자 사이의 데이터 값을 조회하고 싶을 때(BETWEEN START_DATE AND END_DATE)

		* IN (A, B, C) : 목록 중 해당되는 사항이 있을 때

		IN, BETWEEN 둘다 같은 속성인 경우만 비교 가능 / 앞에 not을 붙여 부정 가능

		* LIKE : 문자열 안에서 특정 글자나 패턴을 찾을 때 사용하는 조건문
		WHERE 컬럼명 LIKE 'PATTERN' ( 조회하고 싶은 구문을 PATTERN 자리에 넣음 )
			- LIKE는 포함 여부, 시작 문자, 끝 문자, 특정 글자 패턴을 찾을 수 있음
			- not 사용 가능

			1. % : 글자 수와 상관없이 아무 문자나 여러 개 올 수 있다는 뜻
				ex. 'A%' : A로 시작하는 모든 데이터
				'%A' : A로 끝나는 데이터
				'%A%' : A를 포함하는 데이터
				'A%B' : A로 시작하고 B로 끝나는 데이터

			2. _ : 문자 1개를 의미함
				ex. 'A_' : A로 시작하고 전체 길이가 2인 값
				'A__' : A로 시작하고 전체 길이가 3인 값
				'_A' : A로 끝나고 전체 길이가 2인 값
				'_A_' : 전체 길이가 3이고 A가 정가운데 있는 값

< DCL(Data Controll Language) > : 데이터 제어어
 - 데이터베이스에서 사용자 권한을 관리하는 SQL이다.
 - GRANT : 권한을 부여
 - REVOKE : 권한을 회수

 - DCL이 필요한 이유
	- 모든 사용자에게 모든 권한을 주면 위험해진다.

 - MySQL에서는 사용자를 다음과 같이 구분한다.
	- '사용자명'@'접속자위치'
	- 'teacher'@'localhost' 

사용자 생성하는법
create user '사용자명'@'접속자위치'
identified by '비밀번호';

update account set balance = balance - 1000 where id = 1;
update account set balance = balance + 1000 where id = 2;

commit
- 작업을 최종 확정하는 것을 의미함
