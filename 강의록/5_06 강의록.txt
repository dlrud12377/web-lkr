 < 5/06 강의록 >

 	< 집계 함수(그룹 함수) >
	 - 하나 이상의 행에 대한 값들에 대해 집계(개수, 총합, 평균, 최대, 최소 / COUNT, SUM, AVG, MAX, MIN)하여 하나의 값을 반환
	 - 일반적으로는 일반 속성과 집계함수를 SELECT 절에서 같이 사용할 수는 없다.
	 - NULL값은 집계하지 않는다.

	ex. SELECT AVG(SALARY) FROM EMPLOYEES;

	1. GROUP BY
	 - 같은 데이터를 묶어서 집계할 때 사용하는 문법
	 - 부서별
	 - 상품별
	 - 카테고리별
	
	ex.
	SELECT DEPARTMENT_ID, AVG(SALARY)
	FROM EMPLOYEES
	GROUP BY DEPARTMENT_ID

	조건을 여러개 줄수도 있다.
	ex.
	SELECT DEPARTMENT_ID, JOB_ID, AVG(SALARY)
	FROM EMPLOYEES
	GROUP BY DEPARTMENT_ID, JOB_ID;

	2. HAVING
	- GROUP BY로 만든 그룹을 조건으로 필터링할 때 사용하는 문법
	- WHERE은 -> 전체 행에 대해서 필터링
	- HAVING -> 그룹핑을 한 뒤에 필터링(그래서 집계 함수류와 사용함)

	< 순서 총정리 >
	SELECT
	FROM
	WHERE
	GROUP BY
	HAVING

	3. ROLLUP
	- 결과에 중간 합계와 총 합계까지 자동으로 추가해주는 기능

	4. 정렬(ORDER BY)
	- 조회 결과를 원하는 순서로 정렬할 때 사용하는 문법
	- ASC : 오름차순(작->큰) / DESC : 내림차순(큰->작)
	
	- 형식
	SELECT 칼럼명
	FROM 테이블명
	ORDER BY 정렬기준컬럼 정렬방식;

	** 오름차순
	숫자 : 작 -> 큰
	문자 : 사전순(ㄱ -> ㅎ, A -> Z)
	날짜 : 오래된 날짜 -> 최신 날짜

	 -> 내림차순은 반대

	- 정렬 기준을 여러개 둘 수 있다.
	ORDER BY 정렬컬럼1 정렬방식, 정렬컬럼2 정렬방식...;

	5. 순위를 정하는 함수 (윈도우 함수)
	- ROW_NUMBER() : 무조건 1,2,3,4 처럼 번호를 붙인다.
	- RANK() : 공동 순위를 인정하고, 다음 순위를 건너뛴다.
	- DENSE_RANK() : 공동 순위를 인정하지만, 다음 순위를 건너뛰지 않는다.
	- NTILE(n) : 데이터를 N개의 그룹으로 나눈다.
	- PERCENT_RANK() : 상대적인 순위 비율을 구한다.

	- 형식
	순위함수() OVER( ORDER BY 정렬기준 컬럼 정렬기준 )

	< 인덱스 >

	id	이름		나이
	1	김철수	20
	2	이영희	22
	3	박민수	21
	4	최유리	23

	select * from student where name = '박민수';
	인덱스가 없으면 MySQL은 데이터를 처음부터 하나씩 확인한다.
	이런 방식을 Full Table Scan(전체 테이블 스캔)이라고 한다.

	인덱스 생성 기본 문법
	CREATE INDEX 인덱스명
	ON 테이블명(컬럼명)

	인덱스는 일종의 출석부 역할
	실제 테이블을 이름순으로 바꾸는 게 아니라, 이름순으로 찾기 좋은 별도의 목차를 만듦
	예를 들어 학교에서 전교생 3천명 중 홍길동을 찾기 위해서 일일히 부르는 게 아니라 반별 출석부를 확인하는 느낌
	(3000명 중 홍길동 : 오래걸림 / 5학년 3반 홍길동 : 빠름)

	쿼리를 실행하면 인덱스가 자동으로 사용이 된다.
	select * from student where name = '박민수'

	인덱스 확인하는 방법
	show index from 테이블명;

	인덱스 삭제
	drop index 인덱스명 on 테이블명;

	테이블 만들 때 PK를 설정하면 MySQL은 자동으로 PK 컬럼에 대해서 인덱스를 생성한다.
	그래서 PK를 이용해서 SELECT를 할 때는 빠르게 동작할 가능성이 높다.

	UNIQUE 제약조건도 자동으로 인덱스를 만든다.

	- 인덱스의 장점
		1. SELECT 속도가 향상된다.
			- 검색 조건에 INDEX가 있으면 조회 속도가 빨라질 수 있다.
		2. ORDER BY 성능 향상
			- 정렬을 빠르게 할 수 있다.

	- 인덱스의 단점
		1. 저장공간이 추가로 필요함
			- 인덱스는 별도의 자료구조이기 때문에 테이블 데이터를 저장하는 곳 외에 인덱스 공간이 추가로 필요함
		2. INSERT가 느려질 수 있다.
			- 데이터를 추가할 때 테이블에만 넣는 것이 아니라 인덱스도 같이 갱신해야 한다.
		3. UPDATE가 느려질 수 있다.
			- 인덱스가 걸린 컬럼을 수정하면 인덱스도 다시 정리해야 한다.
		4. DELETE가 느려질 수 있다.
			- 데이터를 삭제할 때도 인덱스에서 해당 값을 정리해야 한다.

	-> 인덱스를 걸면 좋은 컬럼
	1. WHERE 조건에 자주 사용되는 컬럼
	2. JOIN에 자주 사용되는 컬럼
	3. ORDER BY에 자주 사용되는 컬럼
	4, GROUP BY에 자주 사용되는 컬럼

	- 인덱스를 걸면 애매한 컬럼
	 -> 값의 정보가 적은 컬럼
