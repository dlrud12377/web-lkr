 < 4/10 강의록 >

	< Map >
		- Map 인터페이스가 별도로 존재
		- key와 value 두 개의 값으로 구성된다.
		- value의 값은 중복될 수 있으나, 인덱스의 역할을 하는 key는 중복되어선 안된다.

		< HashMap >
			- Map 인터페이스를 구현한 대표적인 클래스
			- put(key, value); : 데이터의 삽입 - key-value 한 쌍의 정보를 넣음
				ㄴ 없으면 추가, 있으면 value의 갱신이 일어남 ( 갱신을 원하지 않으면 putIfAbsent를 사용 )
				-> List에서는 add에 해당
			- get(key) : 해당 key에 연결된 **value의 값** 반환
				ㄴ getOrDefault(key, default) : 해당 key의 value가 있으면 반환, 없으면 default값을 반환
			- containsKey(key) : 해당 key가 포함되어있는지 검사
		 	- containsValue(value) : 해당 value가 포함되어있는지 검사
			- size() : 컬렉션의 크기를 반환(length)
			- remove(key) : map 내 key값에 해당하는 key-value쌍 삭제
			- clear() : map 내 모든 정보 삭제
			- replace
			- keySet(); :  map에 들어있는 모든 key만 추출하여 Set에 저장
			- values() : map에 들어있는 모든 value들만 가져오기(List에 저장 - 중복 허용을 위해서)
			- entrySet() : key-value쌍 데이터 전체를 set 내에 Entry객체로 저장

	


	< 람다식 문법(lambda expression) >

		- 기존의 함수(객체 지향 프로그래밍에서의 메서드) 사용법 : 
			1. 구현 클래스를 만들어 main에서 객체를 생성하고 메서드 호출 후 실행
			2. 인터페이스 생성 시 익명 클래스를 붙여 메서드 호출 후 실행
				ㄴ 어쨌든 객체를 만들어야 해서 코드가 길어짐

		- 람다식 표현법
			 - 반환타입, 메서드명을 생략하고 매개변수와 몸체 사이에 화살표를 쓴다.
				(매개변수) -> {실행문};

		- 람다식 사용의 이유
			1. 코드가 짧아진다.
				- 익명 클래스보다 코드를 짧게 작성할 수 있다.

			2. 핵심 로직이 잘 보인다.
				- 클래스 선언, 메서드 선언과 같은 껍데기를 줄이고 실제로 하고싶은 동작만 보이게 할 수 있다.

			3. 컬렉션 처리에 유용하다.
				- 정렬, 필터링, 반복 처리같은 작업에서 자주 사용된다.

			4. 함수형 프로그래밍 스타일을 일부 사용할 수 있다.

		< 생략법 >

			1. 매개변수가 1개를 때는 소괄호 / 타입 생략 가능
				(x) -> {return x;};
				x -> {return x;}
				ㄴ 두개 이상일 때는 안됨

			2. 매개변수가 2개 이상일 때
				- 타입을 생략하려면 전부 다 생략해야 한다.
				- 소괄호 생략은 불가능하다.

			3. 반환형이 void(반환할 값 없음)이면 중괄호 생략 가능
				3-1. 또는 명령이 return 한 줄이면 return과 중괄호를 함께 생략 가능
					x -> System.out.println(x);
					x -> {return x;};
					x -> x;
			
			4. 함수식을 변수에 담을 수 있다.
				- 변수를 통해서 함수를 호출한다.
				- 매개변수에 함수를 전달한다.
				- 반환값으로 함수를 반환한다.
