[문제 4] UI 상세 설계 단계에서 개별 화면에 단순 명칭 대신 'Page_book_2'와 같은 고유한 화면 ID를 부여해야 하는 실무적인 장점을 3가지 서술하시오.
 화면 ID 라벨링을 하면(사실 모든 라벨링이 가지는 장점이기도 함) -> 식별이 확실해지므로
 - 문서에서 화면을 쉽게 찾을 수 있다.(식별 용이)
 - 개발자와 디자이너가 같은 화면을 기준으로 대화할 수 있다.(협업 용이)
 - 화면 이동 흐름을 명확히 표현할 수 있다.(흐름 및 관계 파악 용이)
 - 테스트 케이스 작성 시 기준으로 사용할 수 있다.(기준 용어 정립)

[문제 5] 사용자가 도서 검색을 하였으나 검색 결과가 존재하지 않는 오류(또는 예외) 상황이 발생했습니다. 웹 접근성(WCAG 2.1)의 오류 안내 원칙에 부합하도록 기획자가 시나리오에 작성해야 할 구체적인 시스템 처리 방식과 메시지 구성 요소를 서술하시오.
 - 시스템 처리 방식 : 어디서, 어떤 오류가 발생했는지 이해하기 쉬운 언어로 사용자에게 안내하고, 상황에 따른 해결책을 제시한다. (무엇이 잘못되었고 어떻게 수정해야 하는지 알려준다.)
 - 메시지 구성 요소 : 잘못된 원인, 수정 방향성 / 해결 방법(ex. "검색 결과가 존재하지 않습니다. 다른 검색어를 입력해주세요.")

[문제 6] 사이트 맵(Site Map)을 시각적인 트리(Tree) 구조나 그림으로만 작성하지 않고, '메뉴 1', '메뉴 2', 'Description' 항목을 포함한 표(Table) 형태로도 병행하여 작성해야 하는 이유를 서술하시오.

 - 그림이나 트리 구조로만 작성하면 사이트 맵의 상세 내용을 설명하기가 어렵기 때문에, 표 형태로 정리하여 그 세부사항을 기록한다.

 강사님 : 트리 구조의 그림은 전체적인 계층 구조를 직관적으로 파악하는데 유리하지만, 각 하위 메뉴가 실제로 어떤 기능을 수행하는지, 어떤 화면 요소를 포함하는지에 대한 상세한 정보를 담기 어렵기 때문에 표 형태의 문서로 세부 내용을 명시하여 보완해야 한다.


[문제 7] 입력 필드가 많거나 절차가 복잡한 파일 업로드 화면 설계 시, 사용자의 입력 오류를 방지하고 서비스 이탈을 막기 위해 UI 시나리오상에 반드시 포함해야 하는 '화면 사용 도움 정보'의 구체적인 예시 2가지를 서술하시오.
-> 실패 및 오류가 많이 일어나는 구간에서 구체적인 방향성 제시
 - 비밀번호 입력 : 비밀번호는 영문, 숫자, 특수문자를 포함하여 8자 이상 입력해주세요
 - 파일 업로드 : JPG, PNG 파일만 업로드할 수 있습니다. 최대 파일 크기는 10MB입니다.
 - 신청서 작성 : 입력한 정보는 신청 완료 후 수정할 수 없습니다. 제출 전 내용을 다시 확인해 주세요.
