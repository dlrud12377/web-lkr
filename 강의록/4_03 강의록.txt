중첩 클래스
 - 인스턴스 내부 클래스 : Outer Class의 inner에서 만들어지는 클래스
 - 정적 내부 클래스(static) : builder 패턴
 - 지역 내부 클래스 : Outer Class의 method 내부에서 만들어지는 클래스 -> 메서드 내부에서 만들어지기 때문에 객체가 어케되지?

특징
 - 외부에 노출되지 않아도 됨(보안성)
 - 


익명 클래스
 - 이름이 없는 클래스
 - 인터페이스와 같이 사용되는 경우가 많음
	-> 인터페이스는 구현할 클래스가 연결되어 객체를 간접 생성해야 하고, 그 역할을 익명 메서드로 하는 것이 편리함
	-> + 재사용하지 않고 간단히 사용할 경우에 강점이 있음

형식 : 
	(1). 일반 인터페이스 구현 클래스
	interface InterA{}
	
	class Impl implements InterA {~}

	class Main{
			public void main(String[] args) {
					Impl impl = new Impl(); // 인터페이스를 구현한 클래스의 객체

				}
			}


	(2). 익명 클래스 활용한 인터페이스
	interface InterA{}

	class Impl { class A }
	
	class Main{
			public void main(String[] args) {
					
					Impl i = new Impl();
					i.method(new A {override~}); -> A 객체를 따로 지정하거나 만들지 않고 사용 후 바로 없어지도록 익명 클래스 사용

				}
			}

다형성
 - 부모타입 클래스 형변환, 오버라이딩, 오버로딩

 < Tip >
정의하면서 매개변수를 받아야 할까? 안 받아도 될까?	
 - 어떤 메서드를 정의하려고 하는가?를 먼저 생각
 - 정의할 때는 매개변수에 값이 들어있지 않음
 - 특정 타입의 값만 전달
 - 매개변수에 어떤 값이 들어올지 예상하고 안에 기능을 만들어야 함(설계 해보니 이 값이 필요하네? 밖에서 받아와야지 -> 매개변수 필요)
 - 메서드 구조는 익숙해져야 함 (접근제한자 반환타입 메서드명(매개변수) {void 아니면 return~})


라이브러리
 - 클래스, 인터페이스의 모음
 - JAR 파일로 존재한다.
 - 자주 재사용하는 클래스, 인터페이스, 메서드 같은 것들을 추출해서 관리한다.

모듈
 - 패키지 관리 기능까지 포함됨
 - 어떤 패키지를 쓸지 말지 결정할 수 있기 때문에 정보 은닉에 좋음( 보안성 up )
 - JAR 파일을 등록하거나, 프로젝트 자체를 참조하는 두 가지 방법이 있음


생성자를 통해서 넣기 -> 접근제한자 클래스명(""매개변수"") {~}

***필드에 값을 넣어주는 법***
1. 필드에 직접 넣기(private이면 불가능)
2. 생성자를 이용해 초기화
3. setter를 통해 대입(가장 추천됨)
